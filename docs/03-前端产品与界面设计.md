> 项目：知枢 NexusKB  
> 前端技术：Vue 3 + TypeScript + Vite + Vue Router + Pinia + Element Plus

## 2. 产品目标

前端需要同时服务两类核心场景：

1. 普通员工快速向企业知识库提问，获得带来源、可核验的回答。
2. 管理人员上传、维护、授权和审计企业文档。

设计原则：

- **可信优先**：知识库答案必须突出来源和页码；通用知识补充必须持续标明“非知识库资料”，不能与有来源
  回答混淆。
- **权限可见**：用户能理解自己为什么看不到内容，但不能暴露无权文档的名称和信息。
- **状态透明**：上传、解析、Embedding、索引等异步步骤必须有清晰进度。
- **操作可控**：删除、重建索引、修改权限等高风险操作需要确认和结果反馈。
- **企业效率**：桌面端优先，支持批量、筛选、键盘操作和稳定信息密度。
- **安全默认**：密钥不回显，敏感内容不写入浏览器持久化存储。
- **避免伪智能**：不展示虚构的“AI 正在思考”步骤，只展示真实可观测状态。

## 3. 用户角色

| 角色 | 主要能力 |
|---|---|
| 普通用户 | 知识问答、查看自己有权访问的来源、查看个人历史 |
| 管理员 | 在 capability 允许时管理文档、部门权限、审计、Provider、用户角色和运维信息 |

每个用户必须且只能有一个角色。管理员也必须受到 tenant、敏感度和 capability 边界约束。前端隐藏无权限入口
只是体验优化，后端仍须对每个 API 强制鉴权。

## 4. 前端技术选型

### 4.1 基础框架

- Vue 3。
- TypeScript strict mode。
- Vite。
- Composition API 与 `<script setup lang="ts">`。
- Vue Router 官方路由。
- Pinia 管理身份、界面偏好等客户端全局状态。
- Element Plus 提供企业后台基础组件。
- 原生 `fetch` 封装或统一 HTTP client；项目中只保留一套请求封装。
- Vitest + Vue Test Utils。
- Playwright 做关键端到端流程。

官方参考：

- [Vue TypeScript 指南](https://vuejs.org/guide/typescript/overview)
- [Vue Router](https://router.vuejs.org/guide/)
- [Pinia](https://pinia.vuejs.org/introduction.html)
- [Element Plus](https://element-plus.org/en-US/guide/quickstart.html)

### 4.2 选择 SPA 而非 SSR

本项目是需要登录的企业后台，不依赖搜索引擎收录。第一阶段使用 Vite SPA，部署简单，且适合与 NestJS API 分离。

如果未来需要公开知识门户或 SEO，再单独评估 Nuxt，不在当前后台中提前引入 SSR 复杂度。

### 4.3 服务端状态与客户端状态

- 文档列表、任务、回答、审计等服务端数据由专用 composable/query 层获取和缓存。
- Pinia 只保存身份摘要、导航状态、主题和非敏感界面偏好。
- API Key、完整文档、完整问答内容不得持久化到 `localStorage`。
- 认证优先使用安全、HttpOnly、SameSite Cookie；若使用 token，遵守后端认证设计，不自行创建不安全持久化方案。

## 5. 信息架构

### 5.1 主导航

```text
知枢 NexusKB
├── 知识问答
│   ├── 新建问答
│   └── 历史记录
├── 知识库
│   ├── 文档管理
│   ├── 上传与入库任务
│   └── 文档详情/版本
├── 权限管理（管理员）
│   ├── 用户与角色
│   └── 部门与文档权限
├── 审计中心（管理员）
│   └── 审计日志
└── 系统管理（管理员）
    ├── 模型 Provider
    ├── 系统状态
    └── 用量与成本
```

采用左侧导航，适合多模块企业后台。问答入口固定在第一项，降低普通用户学习成本。
普通用户侧栏只显示“知识问答”和“问答历史”，不显示空的“管理”分组；所有其他入口仅向同时满足
`admin` 角色和对应 capability 的身份展示。

### 5.2 页面路由

| 路由 | 页面 | 权限 |
|---|---|---|
| `/login` | 登录 | 未登录 |
| `/ask` | 知识问答工作台 | 所有登录用户 |
| `/history` | 我的问答历史 | 所有登录用户 |
| `/documents` | 文档管理 | 管理员 + `documents:read` |
| `/documents/:id` | 文档详情与版本 | 管理员 + `documents:read` + 文档 ACL |
| `/documents/:id/chunks` | 文档分块详情 | 管理员 + `documents:read` + 文档 ACL |
| `/ingestion-jobs` | 上传与入库任务 | 管理员 + `documents:read` |
| `/access/users` | 用户与角色 | 管理员 + `access:read` |
| `/access/departments` | 部门与文档权限 | 管理员 + `access:read` |
| `/audit` | 审计日志 | 管理员 + `audit:read` |
| `/settings/providers` | 模型 Provider | 具备 `system:read` 的管理员 |
| `/system/status` | 系统状态 | 管理员 + `system:read` |
| `/system/usage` | 用量与成本 | 具备 `system:read` 的管理员 |
| `/403` | 无权限 | 所有人 |
| `/:pathMatch(.*)*` | 404 | 所有人 |

路由 `meta` 可以声明所需 capability，但后端响应才是最终权限依据。

## 6. 全局布局

### 6.1 桌面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ Logo / 当前租户             全局状态  帮助  通知  用户菜单   │
├──────────────┬───────────────────────────────────────────────┤
│              │ 面包屑 / 页面标题                 页面操作    │
│ 左侧导航     ├───────────────────────────────────────────────┤
│              │                                               │
│ 知识问答     │                  页面内容                     │
│ 知识库       │                                               │
│ 权限管理     │                                               │
│ 审计中心     │                                               │
│ 系统管理     │                                               │
│              │                                               │
├──────────────┴───────────────────────────────────────────────┤
│ 可选：系统维护/Provider 异常横幅                              │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 布局规则

- 顶栏高度建议 56px。
- 展开侧栏宽度建议 224px，折叠宽度 64px。
- 桌面端使用经典侧边栏 + 顶部面包屑 + 主内容区：顶栏和侧栏固定在视口，侧栏导航独立滚动且分组标题冻结；`app-main` 固定为可用视口高度且不自身滚动。页面以紧凑卡片、清晰间距和高频操作可达性为优先。
- 非问答页面的 `page-heading` 位于 `app-main` 顶部，页面标题和控制区不参与正文滚动；页面顶部留白由 `app-main` 的 `padding-top` 提供，`page-heading` 不承担顶部定位间距；不使用 `position: sticky`。来源路由的“返回”操作放在 `h1` 最右侧，不在正文工具栏或详情内容中重复出现。
- 列表与管理页面的 `xxxx-toolbar` 位于页面标题下方的独立面板。工具栏下方必须使用对应的
  `xxxx-content`（或等价内容块）并设置 `min-height: 0; overflow: auto`；只有该内容块滚动，筛选与主要操作
  始终可见。
- `app-main` 的直接 `section` 统一占满页面可用宽度，与 `page-heading` 左右边界一致。
- 每个 `xxxx-page` 还必须填满标题以下的剩余高度；空、加载和错误状态也在内容块内占用可用空间，避免页面底部
  留出无意义的大面积空白。
- 列表与管理页面的 `xxxx-toolbar` 使用统一的单一工具栏面板（相同内边距、间距、边框和圆角），下方表格或布局使用另一内容面板；文档管理同样拆分为 `documents-toolbar` 与 `documents-content`，不使用包住整个页面的大卡片。分页位于内容面板底部，不额外添加上边框；所有分页统一使用 `layout="total, prev, pager, next"`，不展示总数或每页条数控制。总数分页传入 `total`，游标分页传入可用的 `page-count`。
- 危险或系统级异常使用全局横幅，不只使用容易消失的 toast。
- 页面标题右侧放主要操作，例如“上传文档”。
- 二级页面使用面包屑，问答工作台可省略。

## 7. 登录页

### 7.1 页面目标

提供企业身份登录入口。密码模式只短暂保存表单输入用于提交，不在前端自行保存用户名密码、session token 或账号
配置。

```text
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                    知枢 NexusKB                              │
│              可信、可追溯的企业知识中心                     │
│                                                              │
│             ┌──────────────────────────┐                     │
│             │ 使用企业账号登录         │                     │
│             │                          │                     │
│             │ 账号 [                ] │                     │
│             │ 密码 [                ] │                     │
│             │ [       登录          ] │                     │
│             │                          │                     │
│             │ 开发环境登录（仅本地）   │                     │
│             └──────────────────────────┘                     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

要求：

- `GET /v1/auth/login-options` 返回 `passwordEnabled=true` 时显示账号、密码和提交按钮；其他模式显示组织批准的
  登录方式说明。前端不枚举账号，也不判断账号是否存在。
- 密码仅提交给同源 API；成功或失败后均立即清空输入框，错误提示不区分账号不存在和密码错误。
- 开发身份入口只在后端明确返回 development 模式时说明服务端会自动建立受控身份。
- 登录失败显示可操作信息，不暴露认证服务内部细节。
- 已登录用户访问 `/login` 自动跳转 `/ask`。

## 8. 知识问答工作台

这是普通用户的核心页面，应优先设计和实现。

### 8.1 桌面布局

```text
┌───────────────┬──────────────────────────────────────────────┐
│ 会话列表      │  企业知识助手                    [新建问答] │
│               ├──────────────────────────────────────────────┤
│ 今天          │                                              │
│ · 付款周期    │  用户：付款周期是多久？                     │
│ · 报销材料    │                                              │
│               │  助手：验收完成后 30 天内付款。[来源1]      │
│ 本周          │                                              │
│ · 请假制度    │  ┌ 来源1：财务制度.pdf · 第12页 ─────────┐ │
│               │  │ 付款周期为验收完成后30天……            │ │
│               │  └────────────────────────────────────────┘ │
│               │                                              │
│               ├──────────────────────────────────────────────┤
│               │ [选择知识范围]  输入问题……          [发送] │
└───────────────┴──────────────────────────────────────────────┘
```

### 8.2 首次进入空状态

- 标题：“今天想从知识库了解什么？”
- 展示 3–4 个真实业务示例问题，点击可填入输入框但不自动发送。
- 提示“回答仅基于您有权访问的资料，并附带来源”。
- 不展示夸张营销图或无法验证的能力。

### 8.3 提问交互

- Enter 发送，Shift+Enter 换行。
- 输入为空、仅空白或超过长度限制时禁止发送。
- 发送后输入框保持可取消状态。
- 请求期间显示真实阶段：正在检索资料、正在组织回答；不要伪造详细推理过程。
- 支持停止生成时，仅在后端提供取消能力后启用。
- 请求失败保留用户输入，并提供重试。
- 防止双击或网络重试产生重复消息，使用 clientRequestId。
- 当前会话的每一轮“问题 + 回答”按时间顺序保留在输入框上方；新问题不能覆盖已完成轮次。刷新后的会话仍可在
  “问答历史”中按当前 tenant + user 查看，浏览器不持久化问题或回答正文。
- 在当前登录会话中切换任意导航页后返回“知识问答”，仍展示同一轮次；只有用户点击“新建问答”才清空当前工作台。

### 8.4 回答卡片

回答区域包含：

- 正文，支持受控 Markdown 的标题、段落、列表、引用、代码、表格、强调和安全链接。
- 行内 `[来源N]`，使用小号、次要色标记，与正文建立清晰视觉层级。
- 来源卡片。
- “复制回答”。
- “有帮助/无帮助”反馈。
- trace ID 的可复制入口，默认放在更多菜单。
- 实际模型标识可放详情中，不占用主要阅读区域。
- `answerMode=general` 时，在正文前持续显示“通用知识补充——以下内容来自模型通用知识，不是企业知识库资料，
  仅供参考”，不展示来源卡片；`answerMode=grounded` 才展示知识库来源。

不得显示模型内部 reasoning 或把它描述为事实依据。

### 8.5 来源引用

点击来源卡片打开右侧抽屉：

```text
┌────────────────────────────────────────────┬─────────────────┐
│ 回答内容                                   │ 来源详情        │
│                                            │ 财务制度.pdf    │
│                                            │ 第 12 页        │
│                                            │                 │
│                                            │ 命中片段        │
│                                            │ ……              │
│                                            │                 │
│                                            │ [查看文档详情]  │
└────────────────────────────────────────────┴─────────────────┘
```

- 抽屉只展示后端已授权返回的内容。
- 来源卡片只显示正文中实际出现的 `[来源N]`，不展示仅用于检索或模型上下文、但未被回答引用的条目。
- 页面刷新后重新请求权限，不长期缓存完整片段。
- PDF 页预览属于后续增强；第一版可展示片段、页码和文档 metadata。
- 如果权限在会话后发生变化，显示“来源当前不可访问”，不得展示旧缓存。

### 8.6 混合回答与无答案状态

默认 `hybrid` 模式下，检索不到足够来源时可以显示通用知识补充：

> 通用知识补充
>
> 以下内容来自模型通用知识，不是企业知识库资料，仅供参考。

通用回答的 `noAnswer=false`、`answerMode=general`、`sources=[]`、`model` 为实际 Provider/model。前端不得
伪造来源，也不得把空来源通用回答显示成知识库已验证结论。问答历史沿用同一提示。

严格模式、权限变化、问题出网被阻止或模型不可用时，清楚展示：

> 当前知识库中没有找到足够依据。您可以换一种问法，或联系管理员补充资料。

通用回答不得推测企业制度、内部项目或暗示存在用户无权查看的特定文档。权限在查询期间变化时必须拒答，不能
降级为通用知识。

后端以 HTTP 200 返回 `noAnswer=true`，`reason` 仅用于选择安全提示：`insufficient_relevance` 显示资料不足，
`authorization_changed` 显示“可用来源已发生变化，请重试”。知识库模型输出缺少或越界 `[来源N]` 时，
混合模式可切换到明确标记的通用知识回答；严格模式仍视为资料不足。`noAnswer=true` 响应的
`answerMode=null`、`sources=[]`、`model=null`，前端不得把它渲染成普通模型回答。

## 9. 问答历史页

### 页面内容

- 时间范围筛选。
- 关键词搜索。
- 会话标题、最后更新时间、消息数。
- 删除个人会话入口。
- 空状态和加载骨架。

历史记录只展示当前用户自己的会话。管理员不能通过普通历史页面查看其他用户完整问答；审计需求走审计中心并遵守最小披露原则。

历史详情中的回答与知识问答工作台使用同一个 `SafeMarkdown` 组件和安全策略，避免同一回答在两个页面呈现
不一致。Markdown 原始 HTML 不执行；图片、iframe、脚本、表单、SVG、事件属性、内联样式和危险链接协议均被
移除或转义。安全外链在新窗口打开并增加 `noopener noreferrer`，问题正文仍按普通文本展示。

## 10. 文档管理页

### 10.1 页面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 文档管理                                      [上传文档]     │
├──────────────────────────────────────────────────────────────┤
│ 搜索名称  [部门] [敏感度] [状态] [格式]       [重置]         │
├──────────────────────────────────────────────────────────────┤
│ □ 文件名       状态       部门   敏感度  版本  更新时间 操作 │
│ □ 财务制度.pdf 已生效     财务   内部    v3    今天     ··· │
│ □ 报销说明.docx 处理中 65% 财务  内部    v1    今天     查看│
│ □ 客户名单.xlsx 受策略阻止 销售  机密    v2    昨天     查看│
├──────────────────────────────────────────────────────────────┤
│ 已选择 2 项  [批量修改权限] [批量重新索引]        分页      │
└──────────────────────────────────────────────────────────────┘
```

### 10.2 状态

| 状态 | 表现 | 可用操作 |
|---|---|---|
| 已上传 | 中性 | 查看、开始处理 |
| 处理中 | 进度 + 当前真实步骤 | 查看任务 |
| 待建立索引 | 提示“本地准备完成，尚未生成向量” | 查看详情、继续建立索引、删除 |
| 已生效 | 成功 | 查看、上传新版本、重建、删除 |
| 失败 | 错误 | 查看原因、重试 |
| 策略阻止 | 警告 | 查看策略说明、修改分级 |
| 已删除 | 默认不显示 | 管理员按需查看审计 |

## 11. 上传文档与入库任务

### 11.1 上传对话框

```text
┌──────────────────────────────────────────────┐
│ 上传文档                                     │
├──────────────────────────────────────────────┤
│ 拖放文件到这里，或选择文件                   │
│ 支持 PDF/DOCX/XLSX/MD/TXT/PNG/JPG/DXF/DWG    │
│ 单文件最大值由服务器配置返回                 │
│                                              │
│ 部门       [财务部 ▼]                        │
│ 敏感度     [内部 ▼]                          │
│ 文档说明   [可选……                         ] │
│                                              │
│             [取消] [开始上传]                │
└──────────────────────────────────────────────┘
```

要求：

- 上传前展示格式和大小限制，但后端仍需重新校验。
- 选择 `confidential` 时明确提示默认禁止云端 Embedding。
- 文件上传进度与后续入库进度分开显示。
- 多文件上传时每个文件有独立状态和重试。
- 每次打开上传对话框使用新的文件选择状态；整批文件成功进入服务端队列后关闭对话框，存在失败项时保留对话框供重试。
- 上传文件行使用固定状态列，保证不同长度的状态标签纵向对齐。
- 上传多个文件时，文件列表限制在弹框可用高度内并独立纵向滚动，不得撑高页面产生外层 Y 轴滚动。
- 离开页面不应中断已经进入服务端队列的任务。
- 选择 DWG 时在文件行显示“上传后将安全转换为 DXF 再解析”，不能要求用户预先转换。

### 11.2 入库任务页

展示真实状态机：

```text
排队 → [DWG：CAD 格式转换与解析] / [其他格式：解析] → 分块/脱敏 → Embedding → 建立索引 → 完成
```

进行中任务的耗时在浏览器中每秒更新；服务端任务状态仍按独立轮询节奏刷新。任务结束后耗时冻结在
`completedAt`，不得继续累加。

- 当前步骤高亮。
- 显示开始时间、耗时、尝试次数、warning。
- 错误信息翻译成用户可理解的操作建议。
- 技术详情折叠展示错误码和 trace ID，不展示堆栈或内部路径。
- 只有具备权限的用户能重试或取消任务。
- DWG 处于 `converting` 时展示不确定进度条，主文案为“正在将 DWG 转为 DXF 并解析”，并显示真实已耗时；
  不得用定时器伪造百分比。阶段结束后标记该步骤完成并进入“分块/脱敏”。
- DXF 和其他格式跳过“格式转换”文案，直接显示“正在解析”。多文件上传时，每个 DWG 文件独立显示转换状态。
- 转换器未就绪提示“CAD 转换服务暂不可用，请联系管理员或稍后重试”；格式损坏提示“DWG 文件无效或版本
  不受支持”；`CAD_ENTITY_LIMIT_EXCEEDED` 提示图纸复杂度超过安全上限并建议联系管理员或精简图纸。
  技术详情仍只显示安全错误码和 trace ID。

## 12. 文档详情与版本页

### 页面区块

1. 基本信息：文件名、格式、大小、所有者、部门、敏感度。
2. 当前状态：active version、分块数量、Embedding 指纹摘要。
3. 解析与向量索引摘要：页数、表格数、OCR warning；CAD 显示源格式、转换目标格式、图层/布局摘要和转换
   warning；已建立索引的版本显示 collection 标识、向量数（分块数）、Embedding 指纹和写入时间。提供“查看全部
   分块”入口，以版本选择和服务端分页展示原始文本、写入向量库的脱敏文本、位置、章节、相邻关系和脱敏摘要；
   每次打开均重新按文档 ACL 鉴权，不显示向量值。
4. 版本历史：版本号、上传人、状态、时间。
5. 权限摘要：可见部门、角色和特殊授权。
6. 危险操作：重新索引、上传新版本、删除。

### 高风险确认

- 删除使用二次确认，明确影响“原文件、向量和缓存”。
- 不使用只输入“确认”的弱提示；显示具体文档名和影响范围。
- 重建索引说明旧索引在新索引验证前仍可查询。
- Provider/model/dimensions 变化时提示将创建新索引。
- 当文档为 `prepared`（界面显示“待建立索引”）时，主操作显示“继续建立索引”。确认文案必须说明将复用已保存的
  解析、分块和脱敏结果，不会再次上传或解析原文件；调用同一 reindex API 后仅执行 Embedding 和向量入库。
- 单文档重新索引返回新的 `documentVersion` 和 `jobId`；处理中仍展示旧 active version，只有服务端原子激活
  后才刷新为新版本。失败或策略阻止不得把旧版本渲染为失效。
- 全量 collection 迁移属于平台运维流程。前端只有在后端报告所有候选均已完成且质量评测通过后，才允许展示
  切换确认；切换期间不得自行修改 Provider 配置或推测完成百分比。

第一版不在浏览器直接编辑文档正文。

## 20. API 对接

认证方式、capability/ACL、完整端点目录、错误码、分页和安全调用示例见
[07-API使用说明.md](./07-API使用说明.md)。前端仍以共享 Zod 契约和
`packages/contracts/openapi/api.v1.yaml` 为字段事实源，不从本文手工复制响应类型。

### 20.1 核心接口映射

| 前端功能 | API |
|---|---|
| 文档列表与筛选 | `GET /v1/documents` |
| 上传限制与身份 metadata | `GET /v1/documents/upload-options` |
| 上传文档 | `POST /v1/documents` |

| 查看文档分块 | `GET /v1/documents/:id/chunks` |
| 删除文档 | `DELETE /v1/documents/:id` |
| 重新索引 | `POST /v1/documents/:id/reindex` |
| 入库任务列表/详情 | `GET /v1/ingestion-jobs`、`GET /v1/ingestion-jobs/:id` |
| 重试入库任务 | `POST /v1/ingestion-jobs/:id/retry` |
| 修改授权 metadata | `PATCH /v1/documents/:id/metadata` |
| 知识问答 | `POST /v1/knowledge/query` |
| 我的问答历史 | `GET/DELETE /v1/history/conversations...` |
| 健康状态 | `GET /health/live`、`GET /health/ready` |
| 已验证用户目录 | `GET /v1/access/users` |
| 角色与部门权限 | `PATCH /v1/access/users/:id/roles`、`GET/PATCH /v1/access/departments...` |
| Provider 状态 | `GET /v1/system/providers` |
| 系统状态 | `GET /v1/system/status` |
| 用量摘要 | `GET /v1/system/usage` |

上述接口均使用共享 Zod/OpenAPI 契约；角色/部门 mutation 另需 `access:write`，用量接口另需
`system:read` 与管理员角色。

知识问答请求体只发送 `question`，不能发送 tenant、role、department、任意 Chroma where 或敏感度覆盖值。
429 保留输入并提示稍后重试；响应来源按 `index` 对应正文中的 `[来源N]`，只渲染本次响应返回的来源。

### 20.2 请求封装

- 统一 base URL、credentials、超时和错误映射。
- 自动透传/接收 trace ID。
- 401 统一进入重新认证流程。
- 403 不自动跳登录，显示无权限。
- GET 可按数据类型缓存；权限敏感详情不长期缓存。
- mutation 成功后精确失效相关查询，不做全局粗暴刷新。
- 不对非幂等请求自动无限重试。

### 20.3 实时进度

第一阶段使用轮询查询 ingestion job；轮询采用退避并在页面不可见时降低频率。任务量增加后再评估 SSE/WebSocket。

不要为了进度条提前引入实时连接复杂度。

`converting` 是服务端持久化的真实任务状态。轮询期间使用不确定进度条；只有后端未来提供可验证的转换进度
字段后，才允许切换为确定百分比进度条。

## 22. 路由与权限实现

```ts
declare module 'vue-router' {
  interface RouteMeta {
    requiresAuth?: boolean;
    capabilities?: string[];
    title?: string;
  }
}
```

- 全局 guard 检查登录状态和已加载的 capability。
- 首次加载身份期间显示应用级 skeleton，避免先闪现无权限页面。
- capability 不满足时进入 `/403`。
- `adminOnly` 路由在角色不是 `admin` 时进入 `/403`，即使身份意外携带管理 capability 也不展示或放行管理页。
- API 返回 403 时仍以服务端为准，不能因为前端 capability 判断通过就忽略。
- 页面标题随路由更新。
- 登出后清理内存 store、query cache 和敏感页面状态。

## 23. 响应式设计

### 23.1 唯一断点与实现边界（2026-07-26）

全项目仅使用以下断点，不得在页面或组件中新增 `matchMedia`、`window.innerWidth` 或其他自定义阈值：

| 断点 | 范围 | 布局规则 |
|---|---|---|
| `1280px` | `>= 1280px` | 完整桌面侧栏、会话列表和来源抽屉 |
| `900px` | `901–1279px` | 侧栏折叠，来源抽屉覆盖内容 |
| `768px` | `<= 900px` | 导航切换为 Drawer；`<768px` 为单列和 44px 触控布局 |

`apps/web/src/styles/breakpoints.scss` 是唯一的样式断点声明；Vue 结构分支必须通过
`useBreakpoint()` 的 `isDesktop`、`isTablet`、`isMobile`、`isPhone` 读取。禁止用 CSS `display: none`
同时保留桌面表格和移动端卡片 DOM。列表数据只获取一次，再通过 `v-if` 在桌面表格与移动端卡片组件之间切换。

不新增视口断点的前提下，受侧栏影响的详情操作区与信息卡必须使用 `flex-wrap`、`minmax()` 或 `auto-fit`
按**实际可用内容宽度**连续重排；浏览器拖动缩放时不得等到下一个全局断点才处理溢出。

移动端通用替换规则：

- `el-table` 在 `<=900px` 替换为字段取舍后的卡片列表；标题、状态和操作保持可见，次要字段单列展示。
- 横向筛选表单替换为“筛选”按钮和 `direction="btt"` 的筛选 Drawer；筛选与重置放在同一操作组，并显示已启用条件数量。
- 右侧详情 Drawer 在 `<768px` 使用 `size="100%"`；居中 Dialog 在手机使用底部 Drawer 或全屏 Drawer。
- 危险操作仍必须明确影响范围并要求输入文档名确认；手机端不可降级为普通“确定”。
- 所有 Drawer/Dialog 通过 Teleport 挂到 `body`，顶栏高度 56px，遮罩覆盖应用壳层。
- Element Plus 的全局浮层基线为 `5000`；移动端 Drawer 内的 Select、DatePicker 等 `el-popper` 必须高于 Drawer 与遮罩，禁止页面单独设置冲突的 popper 层级。
- 通过脚本动态切换的 `ElDialog/ElDrawer` 必须显式引入两者的基础 CSS；弹框正文负责短视口滚动，header/footer 保持可见，不能依赖自动组件解析器间接加载样式。
- 文档权限 metadata 编辑在桌面使用标准 Dialog，在手机使用全屏 Drawer；不得用动态组件在两种容器之间切换，以保证表单、页脚和焦点管理稳定。

P0/P1 额外规则：问答输入框保留安全区底部间距；上传 Drawer 隐藏拖放提示且文件列表独立滚动；入库步骤条在
`<768px` 垂直显示；文档详情危险操作在手机吸底；审计卡片默认折叠 Trace ID；用户角色与部门权限在手机使用
展开卡片内的编辑区，不额外打开二级 Drawer。信息区的 `el-descriptions` 在移动端固定单列。

本项目桌面优先，但所有已授权页面都必须在移动端保持可用：

- `>= 1280px`：完整侧栏、会话列表和来源抽屉。
- `901–1279px`：侧栏折叠，会话列表可收起，来源抽屉覆盖内容。
- `<= 900px`：导航统一切换为 Drawer，不保留仅图标的窄侧栏。
- `< 768px`：导航切换为 Drawer，保留当前身份可访问的全部入口（包括 Provider、用量与系统状态）；页面保持可用视口高度且 `app-main` 紧贴视口底部。筛选栏、Provider、系统状态、权限和用量页面均须适配单列布局，主要触控控件最小高度为 44px。

移动端不能让页面整体横向滚动：

- 桌面/平板：表格的横向滚动仅限各自内容块，表头及固定列在该块内保持可见。
- 手机：表格改为带字段标签的信息卡片列表，不让用户在窄屏横向拖动表格。
- 可滚动列表的标题或固定项在该块内保持可见。
- 日期范围控件、Provider 详情及用量卡片不得突破容器。
- 主要操作固定在可达区域。
- 对话输入框适配软键盘。
- 来源抽屉改为全屏 sheet。
- 弹框与 Drawer 遮罩必须覆盖应用侧栏和顶部壳层；Drawer 顶栏与应用顶栏统一为 56px。
- 弹框通过全局 Teleport 挂载到 `body`；宽度不得超过 `100vw - 28px`，正文在可视高度内独立滚动。
- `901–1279px` 的文档筛选区采用可换行 Grid；筛选和重置保持同一操作组，不各自占用一整行。所有筛选提交操作统一命名为“筛选”，不得与“查询”或“应用”混用。
- 信息展示优先使用 `el-descriptions` 或 `div + Flex/Grid` 字段单元；避免以 `dl/dt/dd` 承担页面布局。表单优先使用 Element Plus 控件并保留 `form`、`label`、`button` 等必要语义。
- 展示性段落与列表统一使用 `div + class`，包括受控 Markdown 的段落和列表输出；不在移动端依赖 `p`、`dl/dt/dd`、`ul/li` 的浏览器默认排版。交互与表单优先使用 Element Plus 组件，问答多行输入使用 `el-input type="textarea"`。
- 页面与受控 Markdown 的标题同样统一使用带层级类名的 `div`；通过 `role="heading"` 与 `aria-level` 保留标题导航语义，不使用浏览器对 `h1`–`h6` 的默认字号和边距。
- 在 `<768px`，所有可聚焦的 Element Plus 输入、选择与日期输入文本保持至少 `16px` 字号，避免 iOS 聚焦时触发页面自动缩放；不得通过禁用用户缩放来替代该规则。
- 所有页面的时间范围筛选必须由“开始时间”和“结束时间”两个独立的 `el-date-picker type="datetime"` 组成，不使用 `datetimerange`；手机日期选择浮层通过 `popper-class` 限制为安全视口宽度。用量页的时间控件与日期面板均保留在筛选 Drawer 内。所有底部筛选 Drawer 使用 `72%` 视口高度，正文独立滚动。
- 审计、用户目录、Provider 与系统状态的顶部信息统一收敛到对应的 `xxxx-toolbar` 面板，使用一致的背景、边框、圆角、内边距、标题字号和说明样式；用户目录的身份摘要与筛选不再拆分为两个面板。用量工具栏在桌面端采用介绍与筛选上下布局；移动端的任务、审计、Provider、系统状态和用量工具栏保持单行，说明文字隐藏而主要操作保留在右侧。
- 移动端页面区块使用统一的 `12px` 间距与 `12px` 内边距 token；问答历史固定为上方独立滚动的会话列表和下方独立滚动的详情区。桌面端 `history-layout` 必须占满筛选栏以下的可用高度，左侧列表与右侧详情各自在面板内滚动。会话行与删除入口的触控高度分别不低于 `72px` 和 `48px`。
- 横屏手机（`<=900px` 且高度 `<=500px`）属于低高度移动端：应用顶栏与导航 Drawer 顶栏统一为 `48px`，页面分类与说明隐藏，正文优先保留独立滚动区；用户目录和部门权限由各自内容容器滚动，历史、审计、用量与系统类工具栏收敛为单行右侧筛选/刷新操作。历史页切换为左右双栏，文档详情和移动端信息卡允许双列，禁止横向溢出。

第一阶段验收重点为桌面端 1440px 和常见笔记本宽度 1280px，同时保证 768px 不出现不可操作布局。

## 24. 可访问性

- 所有表单控件有可感知 label。
- 图标按钮有 `aria-label` 和 tooltip。
- 支持键盘完成导航、提问、筛选和关闭弹窗。
- 焦点顺序符合视觉顺序。
- 对话框打开后正确管理焦点，关闭后返回触发元素。
- 错误信息与字段通过 aria 属性关联。
- 动态回答和任务状态使用适当 live region，避免频繁打扰。
- 文字与背景对比度达到 WCAG AA。
- 尊重 `prefers-reduced-motion`。
- 不以颜色作为唯一状态区分。

## 25. 前端安全

- 不在浏览器中调用模型供应商 API。
- 不在前端构建时注入模型 API Key。
- 不信任路由参数、文件名、Markdown 和模型回答。
- 实时与历史模型回答统一使用 `markdown-it`（原始 HTML、自动链接关闭）解析，再经 `DOMPurify` 标签、属性和
  URI 协议白名单清洗；禁止直接渲染未经清洗的 HTML。
- Markdown 链接只允许 `http`、`https`、`mailto` 和站内相对地址，拒绝协议相对 URL；外部链接增加
  `target="_blank"` 和 `rel="noopener noreferrer"`。
- Markdown 图片和其他可发起隐式网络请求的嵌入内容不渲染，避免跟踪像素和越权资源加载。
- 不执行回答或文档中的脚本、iframe 和事件属性。
- 上传文件仍由后端完整校验。
- CSRF、CORS 和 Cookie 策略由前后端联合设计。
- 退出登录清理内存中的权限敏感数据。
- 错误监控在发送前移除问题正文、回答、文档名和 token。
- Provider 密钥输入禁止被通用表单回放、analytics 或 session replay 采集。
