# 企业级知识库前端产品与界面设计

> 项目：知枢 NexusKB  
> 前端技术：Vue 3 + TypeScript + Vite + Vue Router + Pinia + Element Plus  
> 产品形态：企业知识问答工作台与知识库管理后台  
> 当前状态：设计基线，前端实现排在后端最小闭环之后

## 2. 产品目标

前端需要同时服务两类核心场景：

1. 普通员工快速向企业知识库提问，获得带来源、可核验的回答。
2. 管理人员上传、维护、授权和审计企业文档。

设计原则：

- **可信优先**：答案必须突出来源和页码，资料不足时清楚拒答。
- **权限可见**：用户能理解自己为什么看不到内容，但不能暴露无权文档的名称和信息。
- **状态透明**：上传、解析、Embedding、索引等异步步骤必须有清晰进度。
- **操作可控**：删除、重建索引、修改权限等高风险操作需要确认和结果反馈。
- **企业效率**：桌面端优先，支持批量、筛选、键盘操作和稳定信息密度。
- **安全默认**：密钥不回显，敏感内容不写入浏览器持久化存储。
- **避免伪智能**：不展示虚构的“AI 正在思考”步骤，只展示真实可观测状态。

## 3. 用户角色

| 角色 | 主要能力 |
|---|---|
| 普通用户 | 知识问答、查看自己有权访问的来源、查看个人历史 |
| 文档管理员 | 上传文档、维护文档 metadata、查看入库任务、重新索引 |
| 部门管理员 | 管理本部门文档和权限、查看部门使用情况 |
| 审计员 | 查看审计事件与导出，不修改文档和权限 |
| 平台管理员 | 租户范围内的系统配置、Provider 状态、用户角色和运维信息 |

平台管理员也必须受到 tenant 边界约束。前端隐藏无权限入口只是体验优化，后端仍须对每个 API 强制鉴权。

## 4. 前端技术选型

### 4.1 基础框架

- Vue 3。
- TypeScript strict mode。
- Vite。
- Composition API 与 `<script setup lang="ts">`。
- Vue Router 官方路由。
- Pinia 管理身份、界面偏好等客户端全局状态。
- Element Plus 提供企业后台基础组件。
- 原生 `fetch` 封装或统一 HTTP client；项目中只保留一套请求封装。
- Vitest + Vue Test Utils。
- Playwright 做关键端到端流程。

官方参考：

- [Vue TypeScript 指南](https://vuejs.org/guide/typescript/overview)
- [Vue Router](https://router.vuejs.org/guide/)
- [Pinia](https://pinia.vuejs.org/introduction.html)
- [Element Plus](https://element-plus.org/en-US/guide/quickstart.html)

### 4.2 选择 SPA 而非 SSR

本项目是需要登录的企业后台，不依赖搜索引擎收录。第一阶段使用 Vite SPA，部署简单，且适合与 NestJS API 分离。

如果未来需要公开知识门户或 SEO，再单独评估 Nuxt，不在当前后台中提前引入 SSR 复杂度。

### 4.3 服务端状态与客户端状态

- 文档列表、任务、回答、审计等服务端数据由专用 composable/query 层获取和缓存。
- Pinia 只保存身份摘要、导航状态、主题和非敏感界面偏好。
- API Key、完整文档、完整问答内容不得持久化到 `localStorage`。
- 认证优先使用安全、HttpOnly、SameSite Cookie；若使用 token，遵守后端认证设计，不自行创建不安全持久化方案。

## 5. 信息架构

### 5.1 主导航

```text
知枢 NexusKB
├── 知识问答
│   ├── 新建问答
│   └── 历史记录
├── 知识库
│   ├── 文档管理
│   ├── 上传与入库任务
│   └── 文档详情/版本
├── 权限管理（管理员）
│   ├── 用户与角色
│   └── 部门与文档权限
├── 审计中心（审计员/管理员）
│   └── 审计日志
└── 系统管理（平台管理员）
    ├── 模型 Provider
    ├── 系统状态
    └── 用量与成本
```

采用左侧导航，适合多模块企业后台。问答入口固定在第一项，降低普通用户学习成本。

### 5.2 页面路由

| 路由 | 页面 | 权限 |
|---|---|---|
| `/login` | 登录 | 未登录 |
| `/ask` | 知识问答工作台 | 所有登录用户 |
| `/history` | 我的问答历史 | 所有登录用户 |
| `/documents` | 文档管理 | 文档管理员及以上 |
| `/documents/:id` | 文档详情与版本 | 对该文档有管理权限 |
| `/ingestion-jobs` | 上传与入库任务 | 文档管理员及以上 |
| `/access/users` | 用户与角色 | 部门/平台管理员 |
| `/access/departments` | 部门与文档权限 | 部门/平台管理员 |
| `/audit` | 审计日志 | 审计员/平台管理员 |
| `/settings/providers` | 模型 Provider | 平台管理员 |
| `/system/status` | 系统状态 | 平台管理员 |
| `/system/usage` | 用量与成本 | 平台管理员 |
| `/403` | 无权限 | 所有人 |
| `/:pathMatch(.*)*` | 404 | 所有人 |

路由 `meta` 可以声明所需 capability，但后端响应才是最终权限依据。

## 8. 知识问答工作台

这是普通用户的核心页面，应优先设计和实现。

### 8.1 桌面布局

```text
┌───────────────┬──────────────────────────────────────────────┐
│ 会话列表      │  企业知识助手                    [新建问答] │
│               ├──────────────────────────────────────────────┤
│ 今天          │                                              │
│ · 付款周期    │  用户：付款周期是多久？                     │
│ · 报销材料    │                                              │
│               │  助手：验收完成后 30 天内付款。[来源1]      │
│ 本周          │                                              │
│ · 请假制度    │  ┌ 来源1：财务制度.pdf · 第12页 ─────────┐ │
│               │  │ 付款周期为验收完成后30天……            │ │
│               │  └────────────────────────────────────────┘ │
│               │                                              │
│               ├──────────────────────────────────────────────┤
│               │ [选择知识范围]  输入问题……          [发送] │
└───────────────┴──────────────────────────────────────────────┘
```

### 8.2 首次进入空状态

- 标题：“今天想从企业知识库了解什么？”
- 展示 3–4 个真实业务示例问题，点击可填入输入框但不自动发送。
- 提示“回答仅基于您有权访问的资料，并附带来源”。
- 不展示夸张营销图或无法验证的能力。

### 8.3 提问交互

- Enter 发送，Shift+Enter 换行。
- 输入为空、仅空白或超过长度限制时禁止发送。
- 发送后输入框保持可取消状态。
- 请求期间显示真实阶段：正在检索资料、正在组织回答；不要伪造详细推理过程。
- 支持停止生成时，仅在后端提供取消能力后启用。
- 请求失败保留用户输入，并提供重试。
- 防止双击或网络重试产生重复消息，使用 clientRequestId。

### 8.4 回答卡片

回答区域包含：

- 正文。
- 行内 `[来源N]`。
- 来源卡片。
- “复制回答”。
- “有帮助/无帮助”反馈。
- trace ID 的可复制入口，默认放在更多菜单。
- 实际模型标识可放详情中，不占用主要阅读区域。

不得显示模型内部 reasoning 或把它描述为事实依据。

### 8.5 来源引用

点击来源卡片打开右侧抽屉：

```text
┌────────────────────────────────────────────┬─────────────────┐
│ 回答内容                                   │ 来源详情        │
│                                            │ 财务制度.pdf    │
│                                            │ 第 12 页        │
│                                            │                 │
│                                            │ 命中片段        │
│                                            │ ……              │
│                                            │                 │
│                                            │ [查看文档详情]  │
└────────────────────────────────────────────┴─────────────────┘
```

- 抽屉只展示后端已授权返回的内容。
- 页面刷新后重新请求权限，不长期缓存完整片段。
- PDF 页预览属于后续增强；第一版可展示片段、页码和文档 metadata。
- 如果权限在会话后发生变化，显示“来源当前不可访问”，不得展示旧缓存。

### 8.6 无答案状态

清楚展示：

> 当前知识库中没有找到足够依据。您可以换一种问法，或联系文档管理员补充资料。

不要返回看似合理但无来源的答案，也不要暗示存在用户无权查看的特定文档。

```text
├──────────────────────────────────────────────────────────────┤
```

### 10.2 状态

| 状态 | 表现 | 可用操作 |
|---|---|---|
| 已上传 | 中性 | 查看、开始处理 |
| 处理中 | 进度 + 当前真实步骤 | 查看任务 |
| 已生效 | 成功 | 查看、上传新版本、重建、删除 |
| 失败 | 错误 | 查看原因、重试 |
| 策略阻止 | 警告 | 查看策略说明、修改分级 |

状态颜色必须同时配文字或图标，不能只靠颜色表达。

### 10.3 搜索与筛选

- 筛选条件写入 URL query，刷新和分享页面后保持。
- 搜索输入 debounce，但 Enter 可立即查询。
- 服务端分页、排序和过滤。
- 无权限用户不应通过筛选项推断其他部门或文档存在。

要求：


- 显示开始时间、耗时、尝试次数、warning。
- 错误信息翻译成用户可理解的操作建议。
- 技术详情折叠展示错误码和 trace ID，不展示堆栈或内部路径。
- 只有具备权限的用户能重试或取消任务。

## 12. 文档详情与版本页

### 页面区块

1. 基本信息：文件名、格式、大小、所有者、部门、敏感度。
2. 当前状态：active version、分块数量、Embedding 指纹摘要。
3. 解析摘要：页数、表格数、OCR warning。
4. 版本历史：版本号、上传人、状态、时间。
5. 权限摘要：可见部门、角色和特殊授权。
6. 危险操作：重新索引、上传新版本、删除。

### 高风险确认

- 删除使用二次确认，明确影响“原文件、向量和缓存”。
- 不使用只输入“确认”的弱提示；显示具体文档名和影响范围。
- 重建索引说明旧索引在新索引验证前仍可查询。
- Provider/model/dimensions 变化时提示将创建新索引。

第一版不在浏览器直接编辑文档正文。

## 14. 模型 Provider 配置页

仅平台管理员可访问。

### 页面信息

- LLM Provider、模型、base URL 域名摘要、状态。
- Embedding Provider、模型、维度、当前 collection 指纹。
- Rerank 是否启用。
- 最近一次合成检查时间和结果。
- 配额/限流摘要（若后端提供）。

### 密钥安全

- API Key 永不回显；只显示“已配置/未配置”和末尾少量不可用于认证的标识（如果后端安全策略允许）。
- 更新密钥使用 password input，提交后立即清空。
- 前端不得从后端获取现有完整密钥。
- 浏览器不得将密钥写入日志、错误上报、localStorage 或 analytics。
- 保存后由后端执行最小连通性检查并返回脱敏结果。

### Embedding 变更提示

修改 Provider、模型或维度时必须阻止直接覆盖，展示：

> 此修改会改变向量空间，需要创建新索引并重新处理全部 active 文档。旧索引将在验证和切换前保留。

操作入口应创建“索引迁移计划”，而不是直接更新运行配置。

## 15. 审计日志页

### 筛选项

- 时间范围。
- 用户。
- tenant/部门（按当前管理员范围）。

## 17. 统一状态设计

每个数据页面必须实现：

| 状态 | 要求 |
|---|---|
| 首次加载 | 使用结构匹配的 skeleton，避免全页旋转图标 |
| 空数据 | 说明为什么为空，并提供有权限的下一步操作 |
| 无搜索结果 | 保留筛选条件，提供清除筛选 |
| 403 | 不泄露资源详情，提供返回入口 |
| 404 | 明确资源不存在或已删除 |
| 409 | 解释版本冲突并提示刷新 |
| 429 | 展示稍后重试，不进行无限自动重试 |
| 5xx | 保留 trace ID，提供安全重试 |
| 网络离线 | 暂停自动请求，恢复后由用户或策略重试 |
| 部分失败 | 保留成功结果，逐项显示失败原因 |

Toast 只用于短暂成功反馈；需要用户处理的失败应在页面或表单附近持续显示。

## 20. API 对接

### 20.1 核心接口映射

| 前端功能 | API |
|---|---|
| 上传文档 | `POST /v1/documents` |
| 文档详情 | `GET /v1/documents/:id` |
| 删除文档 | `DELETE /v1/documents/:id` |
| 重新索引 | `POST /v1/documents/:id/reindex` |
| 入库任务 | `GET /v1/ingestion-jobs/:id` |
| 知识问答 | `POST /v1/knowledge/query` |
| 健康状态 | `GET /health/live`、`GET /health/ready` |

用户、权限、会话历史、Provider、审计、状态和用量接口需在实现相应页面前补充正式 API 契约。

### 20.2 请求封装

- 统一 base URL、credentials、超时和错误映射。
- 自动透传/接收 trace ID。
- 401 统一进入重新认证流程。
- 403 不自动跳登录，显示无权限。
- GET 可按数据类型缓存；权限敏感详情不长期缓存。
- mutation 成功后精确失效相关查询，不做全局粗暴刷新。
- 不对非幂等请求自动无限重试。

### 20.3 实时进度

第一阶段使用轮询查询 ingestion job；轮询采用退避并在页面不可见时降低频率。任务量增加后再评估 SSE/WebSocket。

不要为了进度条提前引入实时连接复杂度。

## 22. 路由与权限实现

```ts
declare module 'vue-router' {
  interface RouteMeta {
    requiresAuth?: boolean;
    capabilities?: string[];
    title?: string;
  }
}
```

- 全局 guard 检查登录状态和已加载的 capability。
- 首次加载身份期间显示应用级 skeleton，避免先闪现无权限页面。
- capability 不满足时进入 `/403`。
- API 返回 403 时仍以服务端为准，不能因为前端 capability 判断通过就忽略。
- 页面标题随路由更新。
- 登出后清理内存 store、query cache 和敏感页面状态。

## 23. 响应式设计

本项目桌面优先：

- `>= 1280px`：完整侧栏、会话列表和来源抽屉。
- `768–1279px`：侧栏折叠，会话列表可收起，来源抽屉覆盖内容。
- `< 768px`：支持基础问答和查看任务；复杂权限、Provider 和批量文档操作提示使用桌面端。

移动端不能简单压缩桌面表格：

- 文档表格改为卡片列表。
- 主要操作固定在可达区域。
- 对话输入框适配软键盘。
- 来源抽屉改为全屏 sheet。

第一阶段验收重点为桌面端 1440px 和常见笔记本宽度 1280px，同时保证 768px 不出现不可操作布局。

## 25. 前端安全

- 不在浏览器中调用模型供应商 API。
- 不在前端构建时注入模型 API Key。
- 不信任路由参数、文件名、Markdown 和模型回答。
- 模型回答默认作为文本/受控 Markdown 渲染，禁止任意 HTML。
- Markdown 链接使用安全协议白名单；外部链接增加安全属性。
- 不执行回答或文档中的脚本、iframe 和事件属性。
- 上传文件仍由后端完整校验。
- CSRF、CORS 和 Cookie 策略由前后端联合设计。
- 退出登录清理内存中的权限敏感数据。
- 错误监控在发送前移除问题正文、回答、文档名和 token。
- Provider 密钥输入禁止被通用表单回放、analytics 或 session replay 采集。
