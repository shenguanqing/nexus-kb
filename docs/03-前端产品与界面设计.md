## 2. 产品目标

前端需要同时服务两类核心场景：

1. 登录用户快速向知识库提问，获得带来源、可核验的回答。
2. 管理人员上传、维护、授权和审计受管理的文档。

设计原则：

- **可信优先**：知识库答案必须突出来源和页码；通用知识补充必须持续标明“非知识库资料”，不能与有来源回答混淆。
- **权限可见**：用户能理解自己为什么看不到内容，但不能暴露无权文档的名称和信息。
- **状态透明**：上传、解析、Embedding、索引等异步步骤必须有清晰进度。
- **操作可控**：删除、重建索引、修改权限等高风险操作需要确认和结果反馈。
- **效率优先**：桌面端优先，支持批量、筛选、键盘操作和稳定信息密度。
- **安全默认**：密钥不回显，敏感内容不写入浏览器持久化存储。
- **避免伪智能**：不展示虚构的“AI 正在思考”步骤，只展示真实可观测状态。

产品品牌和共享页面统一使用“知识库”、“知识中心”和“知识助手”。后续 Lite 模式的界面范围尚未定义；实现时必须根据服务端返回的模式与 capability 组装导航和页面，不得只用 CSS 或前端条件隐藏未授权功能。

## 3. 用户角色

| 角色     | 主要能力                                                                   |
| -------- | ------------------------------------------------ |
| 普通用户 | 知识问答、查看自己有权访问的来源、查看个人历史                             |
| 管理员   | 当前 tenant 的全部业务与管理功能：文档、部门权限、审计、Provider、后台账号和角色 |

每个用户必须且只能有一个角色。管理员自动获得当前 tenant 的全部 capability 和敏感度访问范围，但不得跨 tenant，也不能绕过 confidential 数据出网策略。前端隐藏无权限入口只是体验优化，后端仍须对每个 API 强制鉴权。

## 4. 前端技术选型

### 4.1 基础框架

- Vue 3。
- TypeScript strict mode。
- Vite。
- Composition API 与 `<script setup lang="ts">`。
- Vue Router 官方路由。
- Pinia 管理身份、界面偏好等客户端全局状态。
- Element Plus 提供管理后台基础组件。
- 原生 `fetch` 封装或统一 HTTP client；项目中只保留一套请求封装。
- Vitest + Vue Test Utils。
- Playwright 做关键端到端流程。

官方参考：

- [Vue TypeScript 指南](https://vuejs.org/guide/typescript/overview)
- [Vue Router](https://router.vuejs.org/guide/)
- [Pinia](https://pinia.vuejs.org/introduction.html)
- [Element Plus](https://element-plus.org/en-US/guide/quickstart.html)

### 4.2 选择 SPA 而非 SSR

本项目当前是需要登录的管理型应用，不依赖搜索引擎收录。前端采用 Vite SPA，部署简单，且适合与 NestJS API 分离。

如果未来需要公开知识门户或 SEO，再单独评估 Nuxt，不在当前后台中提前引入 SSR 复杂度。

### 4.3 服务端状态与客户端状态

- 文档列表、任务、回答、审计等服务端数据由专用 composable/query 层获取和缓存。
- Pinia 只保存身份摘要、导航状态和非敏感界面偏好；主题偏好是浏览器本地 UI 设置，不进入服务端身份或业务状态。
- API Key、完整文档、完整问答内容不得持久化到 `localStorage`。
- 认证优先使用安全、HttpOnly、SameSite Cookie；若使用 token，遵守后端认证设计，不自行创建不安全持久化方案。

## 5. 信息架构

### 5.1 主导航

```text
知枢 NexusKB
├── 知识问答
│   ├── 新建问答
│   └── 历史记录
├── 知识库
│   ├── 文档管理
│   ├── 上传与入库任务
│   └── 文档详情/版本
├── 权限管理（管理员）
│   ├── 用户与角色
│   └── 部门与文档权限
├── 审计中心（管理员）
│   └── 审计日志
└── 系统管理（管理员）
    ├── 模型 Provider
    ├── 系统状态
    └── 用量与成本
```

采用左侧导航，适合多模块管理后台。问答入口固定在第一项，降低普通用户学习成本。普通用户侧栏只显示“知识问答”和“问答历史”，不显示空的“管理”分组；所有其他入口仅向同时满足 `admin` 角色和对应 capability 的身份展示。

主导航选中状态由路由 `meta.activeNavigation` 显式归属，不使用 URL 前缀猜测。文档详情、文档预览和文档分块均归属“文档管理”；进入这些子页时，PC、Pad 和 Mobile sidebar 都必须保持“文档管理”选中，并为当前导航入口提供 `aria-current="page"`。其他页面也必须显式指定对应的一级导航入口，新增子页时同步配置该字段。

### 5.1.1 三档导航形态（2026-08-13）

十个一级入口固定按“问答 / 知识库 / 安全与权限 / 系统”四组组织，组内顺序为：

- 问答：知识问答、问答历史。
- 知识库：文档管理、入库任务。
- 安全与权限：审计中心、用户与角色、部门权限。
- 系统：模型 Provider、用量与成本、系统状态。

PC（`>=1280px`）使用展开、不可折叠的常驻分组侧栏；当前项使用品牌浅色背景和主色文字。Pad（`768–1279px`）保留全部已授权入口的图标，只隐藏文字与分组标题，并在四组之间显示分隔线；鼠标悬停或键盘聚焦图标时只使用 Tooltip 显示当前入口名称，不显示分组标题或创建可点击的二级 flyout；单击图标直接进入对应页面。Pad `app-sidebar` 独立支持 Y 轴滚动，短视口下仍可达全部入口。Pad 顶栏保留服务状态以及由 Element Plus `el-breadcrumb` 统一渲染的“页面分组 / 当前页面”面包屑，仅收起品牌文字和用户详情。Mobile（`<768px`）顶栏使用汉堡菜单、当前页面标题和身份头像；点击汉堡菜单后从左侧展开与 PC 相同分组、顺序和当前项状态的完整 sidebar，选择入口、点击关闭按钮、按 Escape 或点击遮罩后收起。侧栏顶部显示品牌、当前部门与用户，密码会话在底部提供退出登录；页面底部不再常驻导航，也不为菜单预留高度。入口仍必须先经服务端身份派生的 capability 过滤，不得暴露无权限功能。

Mobile sidebar 顶部使用两层结构：首行固定为“品牌 + 关闭”，第二行使用独立身份卡展示用户头像、用户名与部门。长用户名仅在身份卡内省略，不得挤压品牌或关闭入口。

### 6.1 桌面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ Logo / 当前租户             全局状态  帮助  通知  用户菜单   │
├──────────────┬───────────────────────────────────────────────┤
│              │ 面包屑 / 页面标题                 页面操作    │
│ 左侧导航     ├───────────────────────────────────────────────┤
│              │                                               │
│ 知识问答     │                  页面内容                     │
│ 知识库       │                                               │
│ 权限管理     │                                               │
│ 审计中心     │                                               │
│ 系统管理     │                                               │
│              │                                               │
├──────────────┴───────────────────────────────────────────────┤
│ 可选：系统维护/Provider 异常横幅                              │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 布局规则

- 顶栏高度建议 56px。
- 展开侧栏宽度建议 224px，折叠宽度 64px。
- 桌面端使用经典侧边栏 + 顶部面包屑 + 主内容区：顶栏和侧栏固定在视口，侧栏导航独立滚动且分组标题冻结；`app-main` 固定为可用视口高度且不自身滚动。页面以紧凑卡片、清晰间距和高频操作可达性为优先。
- PC/Pad 页面统一使用 Element Plus `el-page-header` 作为 `kb-page-header`：常规页面位于 `app-main` 顶部，问答工作台在自身页面区内复用同一标题、说明和操作结构。标题说明放入 `content` 插槽，页面操作放入 `extra` 插槽；产品返回操作仍位于右侧 `extra`，不使用组件内置左侧返回区。页面标题和控制区不参与正文滚动；页面顶部留白由 `app-main` 的 `padding-top` 提供，`kb-page-header` 不承担顶部定位间距；不使用 `position: sticky`。Mobile 完全不渲染壳层 `el-page-header`；存在返回目标时，在固定 `app-header` 中于汉堡按钮与当前页标题之间显示 ArrowLeft 图标返回入口，通过 `aria-label` / `title` 保留“返回文档列表/详情/会话列表”完整语义，不再为返回操作占用第二行。Mobile 页面标题允许收缩并单行省略；正文工具栏或详情内容不重复返回入口。
- 列表与管理页面的 `xxxx-toolbar` 位于页面标题下方。筛选型 toolbar 直接使用 40px 控件行和布局 gap，不再叠加 `kb-block` 的背景、边框、圆角或 padding；Provider、系统状态等承担状态说明的 toolbar 仍可使用独立面板。多区块详情页使用 `kb-page__content` 承担整页内容滚动；列表页使用 `kb-block-content` 固定内容外壳，再由内部 `kb-block-scroll` 设置 `min-height: 0; overflow: auto`。页面只保留一个主滚动区，筛选与主要操作始终可见；同一节点不得同时使用 `kb-page__content` 和 `kb-block-content`。
- 文档管理与审计中心复用同一 `kb-block-content` / `kb-block-scroll` 结构：内容壳负责剩余高度，Desktop/Pad 的内部滚动块提供边框、圆角和背景；Mobile 使用各自的 `kb-block` 列表卡片，不重复绘制外层边框，外层内容壳与滚动区保持零内距，由列表卡片自身提供内容 padding。任务、分块与用户目录等其他滚动区同样不会被隐式增加 padding。`el-empty.kb-empty-state` 填满可用高度并在水平、垂直方向居中；文档管理在 PC、Pad 与 Mobile 都使用完整 `el-empty` 图形空态，不使用 Element Table 的纯文字 empty slot 代替。分页固定于内容壳底部且不额外添加上边框。
- 文档分块卡片按“分块标题与位置 / Chunk ID / 结构化 metadata / 原始与脱敏正文”四层组织；metadata 直接复用 `kb-data-fields` / `kb-data-field*`，通过 `kb-data-fields--borderless` 移除相邻字段 `border-top`。相邻 Chunk ID 使用“上一个 / 下一个”两行结构，固定标签列并允许 fingerprint 在值列内安全换行。Desktop 与 Pad 正文均为双栏；Mobile 使用 Element Plus“原始内容 / 脱敏后内容”Tabs 且只挂载当前正文。Mobile 分块页是固定工具栏模型的明确例外：整个 `document-chunks-page` 承担纵向滚动，`chunks-toolbar` 随页面滚走，`kb-block-content` / `kb-block-scroll` 不再限制为剩余高度；版本选择填满容器并左对齐。原始正文使用中性灰底，脱敏正文使用低饱和品牌蓝灰底，两者均与白色卡片形成明确层级，同时保持正文对比度和块内滚动。
- `app-main` 的直接 `section` 统一占满页面可用宽度，与 `kb-page-header` 左右边界一致。
- 每个 `xxxx-page` 还必须填满标题以下的剩余高度；空、加载和错误状态也在内容块内占用可用空间，避免页面底部留出无意义的大面积空白。
- 列表与管理页面的筛选型 `xxxx-toolbar` 使用统一的无外壳控制行（相同控件高度和间距），下方表格或布局使用另一 `kb-block-content` 内容区，不为无独立样式、行为或测试用途的节点保留业务 classname。所有仍使用页码分页的页面都将 `kb-pagination` 放在对应 `kb-block-content` 底部，不作为 `kb-page` 的直接子节点；带边框的 `kb-block + kb-block-scroll` 与分页是同级，分页不进入边框、不额外添加上边框并使用透明背景。无内距边框块中的 Desktop Table 由外层 `kb-block` 单独提供容器底边，关闭 Element Table 的底部伪元素、固定列底部补丁与最后一行单元格底边，避免文档管理、审计中心和用户与角色出现第二条终止线；其他行分隔线继续保留。预览降级列表同样使用该内部滚动区与底部分页结构。分页统一使用 `layout="total, prev, pager, next"`，不展示总数或每页条数控制。总数分页传入 `total`，游标分页传入可用的 `page-count`；问答历史是明确例外，使用列表上划追加。
- `documents-toolbar` 与入库任务 `task-controls` 按各自筛选数量在 PC / Pad 中使用单行或两行布局，Mobile 只保留搜索、主要操作与文字“筛选”入口，状态、敏感度和格式等次要条件放入底部筛选 Drawer，不在 Drawer 里重复搜索框。Drawer 内“重置”的语义是清空本页全部筛选条件，包括仍在工具栏中的搜索 Input，并立即重新加载；不得只清 Drawer 内的次要条件。`history-toolbar` 在 PC / Pad 保留会话搜索和筛选/重置操作；Mobile 只保留搜索框与“重置”，用户可通过输入法键盘提交搜索，不再显示“筛选”按钮。三端均不渲染开始时间、结束时间或历史筛选 Drawer。
- 用户目录与用量工具栏复用同一三端节奏，并只承载操作，不重复页面标题或说明。用户目录在 PC 与 Pad 均单行展示搜索、部门、筛选/重置和新增账号，Mobile 保留搜索、新增账号和文字“筛选”，Drawer 只放部门。用量页三端统一展示一个只读的单面板日期范围选择器；PC 与 Pad 同行保留筛选/重置，Mobile 同行保留重置并在范围选完后立即应用，不使用筛选 Drawer。“涉及问答”等必要指标口径放在对应数据卡内，不占用工具栏。
- 审计中心 Mobile 不使用筛选 Drawer；`audit-toolbar` 直接放置可收缩的事件类型 Select 和“重置”按钮，Select 变更后立即应用。
- 危险或系统级异常使用全局横幅，不只使用容易消失的 toast。
- 页面标题右侧放主要操作，例如“上传文档”。
- 二级页面使用面包屑，问答工作台可省略。

## 7. 登录页

### 7.1 页面目标

提供服务端身份登录入口。密码模式只短暂保存表单输入用于提交，不在前端自行保存用户名密码、session token 或账号配置。

```text
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                    知枢 NexusKB                              │
│                可信、可追溯的知识中心                   │
│                                                              │
│             ┌──────────────────────────┐                     │
│             │ 使用账号登录             │                     │
│             │                          │                     │
│             │ 账号 [                ] │                     │
│             │ 密码 [                ] │                     │
│             │ [       登录          ] │                     │
│             │                          │                     │
│             │ 开发环境登录（仅本地）   │                     │
│             └──────────────────────────┘                     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

要求：

- `GET /v1/auth/login-options` 返回 `passwordEnabled=true` 时显示账号、密码和提交按钮；其他模式显示组织批准的登录方式说明。前端不枚举账号，也不判断账号是否存在。
- 密码仅提交给同源 API；成功或失败后均立即清空输入框，错误提示不区分账号不存在和密码错误。
- 开发身份入口只在后端明确返回 development 模式时说明服务端会自动建立受控身份。
- 登录失败显示可操作信息，不暴露认证服务内部细节。
- 已登录用户访问 `/login` 自动跳转 `/ask`。

## 8. 知识问答工作台

这是普通用户的核心页面，应优先设计和实现。

### 8.1 桌面布局

```text
┌───────────────┬──────────────────────────────────────────────┐
│ 会话列表      │  知识助手                        [新建问答] │
│               ├──────────────────────────────────────────────┤
│ 今天          │                                              │
│ · 付款周期    │  用户：付款周期是多久？                     │
│ · 报销材料    │                                              │
│               │  助手：验收完成后 30 天内付款。[来源1]      │
│ 本周          │                                              │
│ · 请假制度    │  ┌ 来源1：财务制度.pdf · 第12页 ─────────┐ │
│               │  │ 付款周期为验收完成后30天……            │ │
│               │  └────────────────────────────────────────┘ │
```

### 8.2 首次进入空状态

- 标题：“今天想从知识库了解什么？”
- 展示 3–4 个真实业务示例问题，点击可填入输入框但不自动发送。
- 提示“回答仅基于您有权访问的资料，并附带来源”。
- 不展示夸张营销图或无法验证的能力。

### 8.3 提问交互

- Enter 发送，Shift+Enter 换行。
- 输入为空、仅空白或超过长度限制时禁止发送。
- 发送后输入框保持可取消状态。
- 请求期间显示真实阶段：正在检索资料、正在组织回答；不要伪造详细推理过程。
- 支持停止生成时，仅在后端提供取消能力后启用。
- 请求失败保留用户输入，并提供重试。
- 防止双击或网络重试产生重复消息，使用 clientRequestId。
- 当前会话的每一轮“问题 + 回答”按时间顺序保留在输入框上方；新问题不能覆盖已完成轮次。刷新后的会话仍可在“问答历史”中按当前 tenant + user 查看，浏览器不持久化问题或回答正文。
- 在当前登录会话中切换任意导航页后返回“知识问答”，仍展示同一轮次；只有用户点击“新建问答”才清空当前工作台。
- 后续轮次携带服务端返回的 `conversationId`。服务端使用近期用户问题理解“它”“前者”等显式指代和“列个需要的材料表格”“材料列个表格”“整理成清单”等动作在前/对象在前的省略主语短连续指令；前端不自行改写问题、不上传本地拼接的历史正文，也不把 tenant、角色、部门或检索过滤器放入请求。

### 8.4 回答卡片

当前交付的回答区域包含：

- 正文，支持受控 Markdown 的 1–6 级标题、段落与换行、有序/无序及嵌套列表、引用、行内/块级代码、分隔线、表格、粗体/斜体/删除线和安全链接。有序列表保留非 1 起始编号；表格保留左/中/右对齐，超宽时只在表格容器内横向滚动且可用键盘聚焦。
- 行内 `[来源N]`，使用小号、次要色标记，与正文建立清晰视觉层级。
- 来源卡片。
- trace ID 和实际模型标识，作为次要运行信息展示。
- `answerMode=general` 时，在正文前持续显示“通用知识补充——以下内容来自模型通用知识，不是知识库资料，仅供参考”，不展示来源卡片；`answerMode=grounded` 才展示知识库来源。

“复制回答”和“有帮助/无帮助”不属于当前交付基线。后续实现反馈时需先定义服务端契约、审计与数据保留规则，不得把回答正文默认发送到 analytics。

不得显示模型内部 reasoning 或把它描述为事实依据。

### 8.5 来源引用

点击行内 `[来源N]` 或回答底部来源卡片打开同编号的来源详情：PC / Pad 使用右侧抽屉，Mobile 使用从视口底部弹起的 bottom sheet：

```text
┌────────────────────────────────────────────┬─────────────────┐
│ 回答内容                                   │ 来源详情        │
│                                            │ 财务制度.pdf    │
│                                            │ 第 12 页        │
│                                            │                 │
│                                            │ 命中片段        │
│                                            │ ……              │
│                                            │                 │
│                                            │ [查看文档详情]  │
└────────────────────────────────────────────┴─────────────────┘
```

- 抽屉只展示后端已授权返回的内容。
- Mobile bottom sheet 复用底部“更多”弹层的圆角面板、顶部拖拽把手和关闭按钮视觉；遮罩覆盖整个视口，打开详情时不跳转页面。点击遮罩、右上角关闭按钮或按 Escape 均可关闭，关闭后仍停留在原问答位置。
- 行内 `[来源N]` 使用紧凑的小号按钮样式，支持鼠标、触摸与键盘操作，并提供“查看来源 N”的可访问名称；无对应后端来源的编号不得触发抽屉。
- 来源卡片只显示正文中实际出现的 `[来源N]`，不展示仅用于检索或模型上下文、但未被回答引用的条目。
- 来源卡片与抽屉只显示实际返回的位置和章节 metadata；未返回时仅保留文档名与版本，不使用“位置未标注”或“未标注章节”之类的占位信息。抽屉底部固定“预览文档”操作，并携带已返回的 page/sheet/version 定位信息。
- 页面刷新后重新请求权限，不长期缓存完整片段。
- 预览页对 PDF 使用浏览器原生查看器并定位引用页，图片/CAD 使用受保护图像内容，TXT/Markdown 使用纯文本或统一 `SafeMarkdown`，Office/CAD 生成产物不可用时展示已授权解析文本和明确降级提示。
- 小型 DXF/DWG SVG 保持 50%–409600% 默认缩放范围；Canvas 瓦片查看器以服务端 manifest 为事实源，配置基准为 z12，远距实体稀释主体时可动态补足到 z15。前端结合最高层级、当前适配比例和最多 2 倍设备像素比限制“放大”，最高瓦片已达到设备一比一细节后禁用继续放大，不把 PNG 再次模糊拉伸。manifest 存在 `focusBounds` 时，首次打开和“重置”以该主体范围居中适配；缺失时保持完整 `bounds` 旧行为。按钮每次按 1.5 倍缩放并以当前视窗中心为锚点，Ctrl/Command + 滚轮每次按 1.25 倍缩放并以指针位置为锚点；SVG 不得只改变图片宽度而遗失缩放前的内容坐标。两种模式都支持缩小、重置、鼠标拖拽平移和全屏，并在右上显示鸟瞰图。所有 CAD 鸟瞰只显示“拖动定位”操作提示；存在 `focusBounds` 时额外提供“主体 / 全图”范围切换。瓦片 focus manifest 默认显示 ACL 保护的“主体”缩略图，可切换“全图”；主体模式的点击、拖动和方向键位置映射回完整坐标，全图模式用蓝框标明小于一个缩略像素的主体位置，橙框继续表示当前视窗。高倍率下真实视窗过小时，交互框保持至少鸟瞰图宽 12%、高 16% 的可拖动尺寸，并用中心点表达真实定位中心。瓦片坐标、平移边界和全图归一化始终使用完整 `bounds`，因此主体模式不得导致远距对象不可达。瓦片模式使用总览图打底，连续平移/缩放停止后只请求最终视口；完整索引已就绪时可见瓦片按距视口中心由近到远优先加载、边缘一圈随后预取，最多并发 2 个请求，使用户视线中心先变清晰。渐进预览在完整索引未就绪时只发送 1 个初始化请求；失败后停止自动预取并保留错误提示，等待用户下一次平移或缩放再重试，不能把所有可见/预取瓦片依次变成重复完整构建。首批细节瓦片成功后恢复 2 并发，并只刷新一次带 cache-buster 的全图与可选主体鸟瞰，使当前会话从快速灰白总览平滑切换到完整彩色几何；刷新失败时保留原总览，不影响已经可用的细节瓦片。离开视口的请求必须取消且不得乱序回填；长会话主动释放淘汰和卸载的 GPU `ImageBitmap`。
- SVG 查看器必须能直接显示 CAD 生成的标准 SVG；服务端将原始 CAD/viewBox 线宽归一为 1–8 屏幕像素，避免非缩放线宽覆盖整个画布。若 `<img>` 已加载且 naturalWidth/naturalHeight 有效但画布纯白，应核对 SVG style 中的线宽换算，而不是误判为空图。
- 渐进瓦片第一次打开时的快速总览也必须保留可确定的实体色和图层色，不使用固定灰白色；中等复杂度图纸还应在受控成本与图元上限内展开块引用，使图框等块内线条首次打开即可见。其文字和曲线精度仍只是加载占位，首批完整细节成功后继续无闪断替换为高层级完整彩色几何总览。
- 对服务端已在 reindex 阶段完成最终几何的渐进 bundle，第一次打开直接显示最终总览；放大加载细节再回到 100% 时图框、填充、文字占位和块内容不得变化。只有服务端提前构建超时或超限的图纸才展示快速占位并在首次细节后刷新，客户端不自行猜测或拼接两套几何。
- Mobile 所有预览类型使用同一紧凑工具栏骨架：文件名与实时权限标记位于左侧信息区，全屏固定在右上，PDF、图片、Office 转 PDF、文本和 Markdown 不保留空的下层操作区。CAD 才在信息区下方追加“缩小 / 当前比例 / 放大”三个等宽列；引用位置存在时单独占一行。长文件名必须为右上全屏保留安全宽度并自然换行，工具栏不得产生水平溢出。
- 瓦片请求失败时保留总览图并提示可重试；总览也失败时显示明确降级状态，不得卡死或留空白。
- 文件名、实时权限校验标记、引用位置和预览操作收入同一紧凑工具栏；PC / Pad 可同行排列，Mobile 按上述通用骨架及 CAD 可选缩放行重排。“每次读取都会重新校验租户、部门与敏感度权限”通过该标记的可访问名称和悬停说明表达。降级文本列表不再只依靠颜色和边框标记 URL 中的引用位置，位置信息继续由工具栏和每个分块的文本标签明确展示。
- 如果权限在会话后发生变化，显示“来源当前不可访问”，不得展示旧缓存。
- 问答历史复用相同行内引用、底部来源卡片和来源抽屉交互；历史详情接口重新鉴权后才返回来源。任一历史引用失效时整轮旧回答隐藏为权限变化状态，不渲染部分来源。
- Web 在滚动升级期间兼容尚未返回 `sources` 的旧历史详情响应，但必须将这类 grounded 旧回答转换为“来源尚未完成重新鉴权”的安全状态，不得展示旧正文，也不得把整个会话误报为响应格式错误。
- 问答历史将当前 `conversationId` 和筛选条件保存在 URL；列表加载位置不作为页码持久化。从来源抽屉进入文档预览时，`from` 参数保留完整历史 URL。点击“返回问答历史”后必须重新校验会话归属、加载同一会话并恢复对应列表项的选中状态。

### 8.6 混合回答与无答案状态

默认 `hybrid` 模式下，检索不到足够来源时可以显示通用知识补充：

> 通用知识补充
>
> 以下内容来自模型通用知识，不是知识库资料，仅供参考。

通用回答的 `noAnswer=false`、`answerMode=general`、`sources=[]`、`model` 为实际 Provider/model。前端不得伪造来源，也不得把空来源通用回答显示成知识库已验证结论。问答历史沿用同一提示。

严格模式、权限变化、问题出网被阻止或模型不可用时，清楚展示：

> 当前知识库中没有找到足够依据。您可以换一种问法，或联系管理员补充资料。

通用回答不得推测特定个人、团队或组织的内部制度、内部项目，也不得暗示存在用户无权查看的特定文档。权限在查询期间变化时必须拒答，不能降级为通用知识。

问题中的图纸、文件名、楼栋或项目线索已被服务端在当前 ACL 内匹配为明确文档范围时，该问题按内部文档事实处理：资料不足时展示无答案状态，不展示“通用知识补充”。

后端以 HTTP 200 返回 `noAnswer=true`，`reason` 仅用于选择安全提示：`insufficient_relevance` 显示资料不足，`authorization_changed` 显示“可用来源已发生变化，请重试”。知识库模型输出缺少或越界 `[来源N]` 时，混合模式可切换到明确标记的通用知识回答；严格模式仍视为资料不足。`noAnswer=true` 响应的 `answerMode=null`、`sources=[]`、`model=null`，前端不得把它渲染成普通模型回答。

## 9. 问答历史页

### 页面内容

- 关键词搜索。
- 会话标题、最后更新时间、消息数。
- 删除个人会话入口。
- 空状态和加载骨架。
- PC、Pad 与 Mobile 的会话列表都在同一内容卡片内滚动，不增加“会话列表”区块标题，也不渲染页码分页。列表面板和真实滚动节点分别复用 `kb-block-content` / `kb-block-scroll`，不保留只重复 Flex/overflow 的中间容器 class。整行会话入口使用不声明 button/listitem role 的 `div`，保留 `tabindex="0"` 与 Enter/Space 响应；标题与摘要使用 `span + kb-text*`，仅保留单行省略所需的页面专属 class。用户上划至列表底部附近时，前端使用当前已加载数量作为 `offset` 请求下一批并追加；请求期间必须防止并发重复加载，筛选、重置或删除后从首批重新加载。

响应式规则：

- PC（`>=1280px`）保持左侧会话列表、右侧详情的双栏布局。筛选栏使用 32px 高单行布局，只保留会话搜索和筛选/重置操作，不显示开始时间、结束时间。列表删除入口使用图标按钮，只在该行 hover 或键盘聚焦时显示。
- Pad（`768–1279px`）保持双栏但收窄列表列；`history-toolbar` 与 PC 一致使用单行布局，搜索框占用剩余宽度，筛选/重置操作组固定靠右，不渲染时间控件。
- PC 与 Pad 每次提交新搜索或重置筛选时都清空当前会话选中状态与 URL `conversationId`，右侧详情恢复“选择一个会话查看内容”空块，不保留搜索前的旧会话。
- Mobile（`<768px`）只渲染会话列表或会话详情其中一级：应用顶栏使用汉堡菜单、可选 ArrowLeft 返回入口、可收缩的页面标题和身份头像，页面正文不重复标题说明；列表页顶部保留搜索框和外置“重置”，不显示“筛选”按钮、开始/结束时间或历史筛选 Drawer；无会话时 `el-empty` 必须填满列表的剩余高度并双轴居中。点击会话进入全宽详情后，固定应用顶栏的 ArrowLeft 入口提供“返回会话列表”语义，不再渲染独立 `el-page-header` 行；详情卡片顶栏只保留省略的会话标题，侧向 sidebar 继续由顶栏汉堡按钮按需展开。完整问题仍在正文中显示；会话列表上划到底部附近时追加下一批。
- Mobile 列表不常驻显示删除文字或按钮。左滑会话行后露出删除图标，删除仍须二次确认；键盘聚焦删除入口时也必须可见，不能把触摸手势作为唯一操作路径。

历史记录只展示当前用户自己的会话。管理员不能通过普通历史页面查看其他用户完整问答；审计需求走审计中心并遵守最小披露原则。

历史详情中的回答与知识问答工作台使用同一个 `SafeMarkdown` 组件和安全策略，避免同一回答在两个页面呈现不一致。Markdown 原始 HTML 不执行；图片、iframe、脚本、表单、SVG、事件属性、内联样式和危险链接协议均被移除或转义。安全外链在新窗口打开并增加 `noopener noreferrer`，问题正文仍按普通文本展示。

### 10.2 状态

| ---------- | -------------------------------- | ---------------------------- |
| 已上传     | 中性                             | 查看、开始处理               |

| 已删除     | 默认不显示                       | 管理员按需查看审计           |

状态颜色必须同时配文字或图标，不能只靠颜色表达。

`deleting` 表示删除已开始但补偿尚未完成。该记录在授权文档列表默认可见，文件名不链接到已关闭读取能力的详情页；具备 `documents:delete` 的管理员可输入完整文件名后调用同一幂等 DELETE 继续清理。完成后记录从默认列表消失，相同 ACL 范围的内容才可重新上传。

文档列表的错误态、数据列表与空态必须互斥渲染。首次加载或筛选请求失败时只显示错误说明与重试入口，不同时显示表头或“暂无符合条件的文档”。

### 10.3 搜索与筛选

- 筛选条件写入 URL query，刷新和分享页面后保持。
- 搜索输入 debounce，但 Enter 可立即提交筛选。
- 服务端分页、排序和过滤。
- 无权限用户不应通过筛选项推断其他部门或文档存在。

## 11. 上传文档与入库任务

### 11.1 上传对话框

```text
┌──────────────────────────────────────────────┐
│ 上传文档                                     │
├──────────────────────────────────────────────┤
│ 拖放文件到这里，或选择文件                   │
│ 支持 PDF/DOC/DOCX/XLSX/MD/TXT/PNG/JPG/DXF/DWG│
│ 单文件最大值由服务器配置返回                 │
│                                              │
│ 部门       [财务部 ▼]                        │
│ 敏感度     [内部 ▼]                          │
│ 文档说明   [可选……                         ] │
│                                              │
│             [取消] [开始上传]                │
└──────────────────────────────────────────────┘
```

要求：

- 上传前展示格式和大小限制，但后端仍需重新校验。
- 选择 `confidential` 时明确提示默认禁止云端 Embedding。
- 文件上传进度与后续入库进度分开显示；浏览器上传使用同源、带凭据和超时的 XHR 获取真实字节进度，不伪造百分比，服务端响应继续执行运行时 schema 验证和统一安全错误映射。
- 多文件上传时每个文件使用独立卡片：上传中展示文件名、大小、进度条和真实百分比；失败展示红色 `failed` 标签、原因、重试和删除；已排队展示绿色 `queued` 标签。删除失败项只移除尚未进入服务端队列的本地选择记录，并同步清理上传组件内部文件列表。
- 每次打开上传对话框使用新的文件选择状态；整批文件成功进入服务端队列后关闭对话框，存在失败项时保留对话框供重试。
- 文件卡片在三端共用同一状态结构：文件名与大小/标签同行，进度或错误位于下方，重试与危险色删除操作保持在错误行右侧；小屏允许文件名换行，不得挤压标签和操作。
- 上传多个文件时，文件列表限制在弹框可用高度内并独立纵向滚动，不得撑高页面产生外层 Y 轴滚动。
- PC 使用约 460px 居中 Dialog，Pad 收窄为约 400px，两者均保留拖放区、只读 metadata、文件队列和分隔的底部操作区。
- 短视口下上传 Dialog 不得超出可视高度；header/footer 保持可见，仅 Dialog body 承担纵向滚动。
- Mobile 上传 Drawer 使用 100% 视口尺寸的底部全屏卡片，正文顶部显示唯一、整行的“选择文件”主按钮，不保留桌面拖放面板和确认发送说明。正文独立滚动，“取消 / 开始上传”等宽吸底并始终可达。
- 离开页面不应中断已经进入服务端队列的任务。
- 选择 DWG 时在文件行显示“上传后将安全转换为 DXF 再解析”，不能要求用户预先转换。

### 11.2 入库任务页

入库任务筛选区遵循第 6.2 节的三端工具栏规则：PC 与 Pad 均为“文档 ID + 状态 + 筛选/重置”单行，Mobile 只保留文档 ID 和“筛选”入口，状态放入底部 Drawer。Drawer 不重复文档 ID 输入框，其“重置”同时清空 Drawer 状态和工具栏文档 ID。非空文档 ID 必须在前端先校验为完整 UUID，非法值只显示工具栏字段错误，不发起 API 请求、不切换为页面加载失败态。页面处于校验错误或 API 错误态时不显示上一次 `total` 对应的分页。

展示真实状态机：

```text
排队 → [DWG：CAD 格式转换与解析] / [其他格式：解析] → 分块/脱敏 → Embedding → 建立索引 → 完成
```

进行中任务的耗时在浏览器中每秒更新；服务端任务状态仍按独立轮询节奏刷新。任务结束后耗时冻结在 `completedAt`，不得继续累加。

- 任务列表使用“摘要行 + 按需展开详情”。`queued`、`converting`、`parsing`、`chunking`、`policy_check`、`embedding`、`indexing` 等进行中状态和 `failed` 默认展开；`completed` 及其他终态默认收起。用户手动切换后保留当前页内选择，不被状态轮询覆盖。
- 收起行不挂载完整步骤条、字段清单、warning 和错误详情，只显示文件名、版本/任务类型、7 个进度点、状态标签和展开指示；Mobile 可隐藏进度点以保证标题和状态可读。摘要行支持鼠标、触摸和键盘 Enter/Space 展开或收起。
- 状态标签、状态筛选和任务类型使用同一展示字典，由 `ingestion-presentation.ts` 集中维护；`ingestion`、`reindex` 和 `index_migration` 在界面中分别显示为“文档入库”、“重建索引”和“索引迁移”。
- PC 展开后保持横向步骤条；Pad 每个步骤项保持可读宽度，在任务内部横向滚动，不压缩或换行步骤文字。滚动视口自身负责完整背景和圆角，步骤内容背景透明，横向滚动时不得露出白色缺口。Mobile 继续使用垂直步骤清单，长文件名必须在摘要行内省略，任务列表不得产生 X 轴滚动。摘要行点击仅切换展开，原文档跳转使用展开详情内的明确入口。

- 当前步骤高亮。
- 显示开始时间、耗时、尝试次数、warning。
- 文档详情索引说明与入库任务 warning 复用同一展示字典，将 Parser 稳定提示码转换为中文标题和说明；已知的 CAD/DXF、DWG、OCR、Tika 与预览降级提示不直接回显英文码，未知新码使用中文兜底并保留技术码供排障。
- 入库任务 warning 与 error 使用相同的 `kb-block__header + kb-data-fields/kb-data-field`“标题 / 标签-内容列表 / 可选操作”布局；warning 使用 warning-soft 背景与 warning 文字，error 使用 danger-soft 背景与 danger 文字。状态色由 feedback 容器提供，块内字段 label/value 继承该颜色，避免公共字段基线色覆盖语义色。文档详情的 `index-warning-list` 直接组合 `kb-data-fields`，整个列表使用与任务 warning 相同的 warning-soft 背景和 warning 文字；内部行只使用 `kb-data-field`，字段标签与 `conversion-note` 一致追加 `kb-text--medium`，说明正文保持常规字重。
- Embedding 已开始且总分块数已知时，显示服务端返回的“已完成 chunk / 总 chunk”；不得用浏览器定时器推算批次进度。
- 错误信息翻译成用户可理解的操作建议。
- 技术详情折叠展示错误码和 trace ID，不展示堆栈或内部路径。
- 只有具备权限的用户能重试或取消任务。CAD 实体、DWG 转换产物和 Parser 元素容量错误不会自动消耗队列重试次数，但管理员完成代码或受控容量调整后，任务详情必须显示人工“重试任务”入口，复用原始文件而不要求删除后重新上传。
- DWG 处于 `converting` 时展示不确定进度条，主文案为“正在将 DWG 转为 DXF 并解析”，并显示真实已耗时；不得用定时器伪造百分比。阶段结束后标记该步骤完成并进入“分块/脱敏”。
- DOC、DXF 和其他格式跳过“格式转换”文案，直接显示“正在解析”。DOC 正文由内网 Tika 提取，预览由本地 LibreOffice 转为 PDF；多文件上传时，每个 DWG 文件独立显示转换状态。
- 转换器未就绪提示“CAD 转换服务暂不可用，请联系管理员或稍后重试”；格式损坏提示“DWG 文件无效或版本不受支持”；`CAD_ENTITY_LIMIT_EXCEEDED` 提示图纸复杂度超过安全上限并建议联系管理员或精简图纸。技术详情仍只显示安全错误码和 trace ID。

## 12. 文档详情与版本页

### 页面区块

1. 基本信息：文档 ID（完整 UUID，提供复制入口）、文件名、格式、大小、所有者、部门、敏感度。入库任务保留按该 UUID 精确筛选，避免同名文件产生歧义。
2. 当前状态：active version、分块数量、Embedding 指纹摘要。
3. 解析与向量索引摘要：页数、表格数、OCR warning；CAD 显示源格式、转换目标格式、图层/布局摘要和转换 warning；已建立索引的版本显示 collection 标识、向量数（分块数）、Embedding 指纹和写入时间。提供“查看全部分块”入口，以版本选择和服务端分页展示原始文本、写入向量库的脱敏文本、位置、章节、相邻关系和脱敏摘要；每次打开均重新按文档 ACL 鉴权，不显示向量值。
4. 版本历史：版本号、上传人、状态、时间。
5. 权限摘要：可见部门、角色和特殊授权。
6. 危险操作：重新索引、上传新版本、删除。

响应式布局：

- PC（`>=1280px`）的“基本信息 / 当前向量索引”使用等宽双卡并排，标题卡右侧直接展示预览、修改权限、重新索引和删除操作。`detail-actions` 与分块页 `chunks-toolbar` 一样作为页面直接顶部行保持可见，下方 `detail-content.kb-page__content` 独立滚动。
- Pad（`768–1279px`）将两张摘要卡纵向堆叠，标题与操作组分行；版本历史继续使用卡片内的紧凑表格。`detail-actions` 同样固定在独立内容滚动区之上。
- Mobile（`<768px`）只在标题卡右上角保留“⋯”入口，预览、修改权限 metadata、重新索引和删除文档收进底部操作面板；删除项持续使用红色警示色，其他操作使用中性文字。摘要、版本和最近任务均使用卡片，不挂载桌面操作组或版本表格。Mobile 改由整个 `document-detail-page` 滚动，标题操作卡可随页面移走，避免固定区域持续压缩正文。
- DWG active version 包含转换 warning 时，将 `DWG_CONVERTED_TO_DXF` 与源版本信息合并为蓝色“格式转换说明”卡片；其他 parser warning 继续独立展示，不丢弃现有详情字段。
- 页面根布局、标题操作栏、标题/操作区、危险与 warning 文本、最近任务字段行优先复用 `main.css` 的 `kb-page`、`kb-status-toolbar`、`kb-title-group`、`kb-action-group`、`kb-block__title`、`kb-text--*` 和 `kb-data-*`；双卡列数、DWG 说明与移动操作面板继续由详情页 scoped CSS 维护。移动操作面板内的导航保留 `RouterLink`，非导航操作使用 `el-button`；不声明 `menu/menuitem` role，避免在未实现方向键 Menu 交互模型时覆盖原生链接/按钮语义。Element Button 内部 wrapper 的 `display: contents` 规则必须同时限定 `.el-button.mobile-action-item`，不得命中预览链接的文字和右侧箭头。继续清理、永久删除和重新/继续建立索引复用 `DocumentDangerConfirm` 文档名强确认组件；正文同级内容间距由 `document-danger-confirm__body` 的 `gap` 统一管理。全局 Dialog 参考 Drawer 使用标题栏、独立滚动正文和操作 footer 三段式布局：根容器不设 padding，header/body/footer 在 PC 与 Pad 均使用 `--kb-block-padding` 四边等宽内距，header 的 `border-bottom` 与 footer 的 `border-top` 横跨整个弹层；关闭按钮参与 Header Flex 布局，不再依赖额外右侧 padding。底部 Drawer 额外保留把手和安全区。
- 交互按钮按语义使用 primary、success、warning、danger、info 色；所有 typed plain Button 使用 surface 背景、对应语义色文字与边框，hover 才填充语义色。危险色 hover 与所有禁用按钮必须在浅色和深色主题保持足够的文字、边框与背景区分度。表格行操作使用 Element Plus 默认 `link` Button：不覆盖其默认 hover 颜色、透明背景、文字高度或内边距；带边框的 typed `plain` Button 用于工具栏、弹层 footer 和其他需要明确控件边界的操作。
- Element Plus 的 `light-3/5/7/8/9` 与 `dark-2` 色阶必须按官方的渐变语义保留不同层级，不能将多个等级映射到同一个 soft token；浅色主题的 `light-*` 向 surface 混合，深色主题向当前 surface 混合，`dark-2` 按主题向相反前景收敛。
- 移动文档操作面板的非导航项与回答来源卡片使用带 `role="button"`、`tabindex="0"` 和 Enter/Space 支持的 `div`，避免继承通用 Element Button 基线；前者固定 48px 高度与紧凑水平内距，后者按内容自适应高度完整显示来源编号、文件名和位置/版本。禁用的移动操作用 `aria-disabled` 说明且不响应点击或键盘操作。
- 所有未显式关闭的 Drawer 内置关闭控件均以 `.el-drawer .el-drawer__close-btn` 命中，强制使用同一 40px 圆形外框、边框和 hover/focus/active 状态；不得因局部加载顺序退化为无边框方形按钮。
- 所有 `el-button is-circle`（包括移动导航关闭按钮）必须以与通用 Button 基线等价或更高的选择器优先级明确设为 `border-radius: 50%`，不能只设置等宽高；移动导航关闭按钮不再保留重复业务 class，仅以可访问名称供测试定位。

### 高风险确认

- 删除使用二次确认，明确影响“原文件、向量和缓存”。
- 不使用只输入“确认”的弱提示；显示具体文档名和影响范围。
- `deleting` 墓碑的“继续清理删除”也使用同一确认结构，并明确它会永久清理残留的原文件、预览、向量和缓存。
- 重建索引说明旧索引在新索引验证前仍可查询。
- Provider/model/dimensions 变化时提示将创建新索引。
- 当文档为 `prepared`（界面显示“待建立索引”）时，主操作显示“继续建立索引”。确认文案必须说明将复用已保存的解析、分块和脱敏结果，不会再次上传或解析原文件；调用同一 reindex API 后仅执行 Embedding 和向量入库。
- 单文档重新索引返回新的 `documentVersion` 和 `jobId`；处理中仍展示旧 active version，只有服务端原子激活后才刷新为新版本。失败或策略阻止不得把旧版本渲染为失效。
- 全量 collection 迁移属于平台运维流程。前端只有在后端报告所有候选均已完成且质量评测通过后，才允许展示切换确认；切换期间不得自行修改 Provider 配置或推测完成百分比。

第一版不在浏览器直接编辑文档正文。

## 14. 模型 Provider 配置页

具备 `system:read` 的管理员可访问；保存和发布分别由后端校验 `system:configure`、`system:deploy`。当前 `admin` 自动拥有这些 capability。

### 页面信息

- LLM Provider、模型、base URL 域名摘要、状态。
- Embedding Provider、模型、维度、当前 collection 指纹。
- Rerank 是否启用。
- 最近一次合成检查时间和结果。
- 配额/限流摘要（若后端提供）。
- 凭据状态：云端 Provider 显示“已配置/未配置”；本机 Ollama Embedding 与本地 BGE Rerank 显示“本地无需凭据”。内部服务 token 仅用于服务间认证，不属于页面展示的 Provider 凭据，且不得回显。

### 密钥安全

- API Key 永不回显；只显示“已配置/未配置”和末尾少量不可用于认证的标识（如果后端安全策略允许）。
- 更新密钥使用 password input，提交后立即清空。
- 前端不得从后端获取现有完整密钥。
- 浏览器不得将密钥写入日志、错误上报、localStorage 或 analytics。
- 保存后由后端执行最小连通性检查并返回脱敏结果。

### 版本发布与回滚

- “编辑运行配置”按 LLM、Rerank 与问答、上传与入库、Parser、CAD/DWG、Tika 分成独立区块。长表单使用 Element Plus Anchor：桌面端为表单左侧纵向锚点；平板和移动端必须同步切换为表单顶部单栏横向导航，使用“Rerank”“入库”“CAD”等紧凑标签和缩减后的项间距，375px 下不得裁切入口，必要时仅导航块内部横向滚动。滚动容器固定为当前页面内容块，不改变 URL 路由语义。
- Provider 页面必须填满应用壳层分配的可用高度，顶部工具栏固定在页面内容块之外；Provider 摘要、运行配置表单和发布记录统一由 `.kb-page__content` 纵向滚动，不能被应用壳层的 `overflow: hidden` 裁切。
- “保存并发布”先创建不可变配置版本，再创建异步发布任务；前端不能发送 Docker 命令或自选服务。
- 页面显示“排队中 / 发布中 / 已生效 / 已自动回滚 / 失败”、配置版本的变更原因、受影响服务和稳定错误码，并在 API 重建短暂不可用时继续有限轮询。
- deployment-agent 未启用时仍可查看 Provider 摘要，但保存按钮禁用并持续显示原因。
- readiness 失败由代理自动恢复上一版本；成功发布且存在上一版本时显示人工回滚入口，回滚仍创建新的受控发布任务并要求确认。
- 桌面与 Pad 发布记录使用固定高度的 Element Table，由表格内部滚动并保持表头固定；`<768px` 使用有最大高度且块内滚动的单列卡片，不保留隐藏表格 DOM。密钥字段在成功或失败后清空，不进入 Pinia、URL 或浏览器持久化。

### Embedding 变更提示

修改 Provider、模型或维度时必须阻止直接覆盖，展示：

> 此修改会改变向量空间，需要创建新索引并重新处理全部 active 文档。旧索引将在验证和切换前保留。

操作入口应创建“索引迁移计划”，而不是直接更新运行配置。

## 16. 系统状态与用量

用量页的 Provider/模型表按查询审计聚合；表格将 `requests` 展示为“涉及问答”，表示该问答使用了对应的 Query Embedding、LLM 或实际执行的 Rerank 阶段，不得描述成供应商账单请求数。一次问答可同时计入 Embedding 与 LLM。当前生效的 Embedding Provider/model 在尚无查询时仍以“涉及问答=0”展示，避免配置刚切换后页面为空；该记录不包含文档入库批次，也不推断 token 或成本。

### 系统状态页

展示：

- API、Parser Worker、PostgreSQL、Redis、Chroma 状态。
- 入库队列长度和最老任务等待时间。
- 最近解析失败。
- Provider 合成检查。
- 磁盘和备份状态摘要。

状态页不能直接展示内部 IP、密码、完整异常堆栈或密钥。

### 用量与成本页

- 开始日期与结束日期按本地自然日筛选；开始日期覆盖当天 00:00，结束日期覆盖当天 23:59:59.999。
- 日期选择器只允许通过日历选择日，不允许键盘输入。手机端直接在工具栏展示 `daterange + single-panel` 日期范围控件，选完立即应用，不使用筛选 Drawer；日期面板 Teleport 到全局浮层容器，并限制在手机安全视口内。
- 按 Provider/model 的关联问答量、token/字符、估算成本；真实供应商调用量以 Provider telemetry/账单为准。
- Token 分为输入与输出；包括 Embedding/Rerank 没有输出 token 语义在内的所有未知值统一显示“暂无数据”，不得在同一页面混用“—”。问答期间实际 Provider telemetry 已持久化且 Provider 回传 usage 时展示累计值；迁移前历史、Provider 未回传字段或价格缺失继续显示“暂无数据”。
- 按 tenant/部门的授权汇总。
- 查询样本数、P50、P95 和失败率；样本量较小时应结合查询次数解释 P95，不把单个最大值误作稳定趋势。
- Embedding、Rerank 和 LLM 分开统计。
- 数据不足时显示“暂无数据”，不补零制造趋势。

## 17. 统一状态设计

每个数据页面必须实现：

| 状态       | 要求                                      |
| ---------- | ----------------------------------------- |
| 首次加载   | 使用结构匹配的 skeleton，避免全页旋转图标 |
| 空数据     | 说明为什么为空，并提供有权限的下一步操作  |
| 无搜索结果 | 保留筛选条件，提供清除筛选                |
| 403        | 不泄露资源详情，提供返回入口              |
| 404        | 明确资源不存在或已删除                    |
| 409        | 解释版本冲突并提示刷新                    |
| 429        | 展示稍后重试，不进行无限自动重试          |
| 5xx        | 保留 trace ID，提供安全重试               |
| 网络离线   | 暂停自动请求，恢复后由用户或策略重试      |
| 部分失败   | 保留成功结果，逐项显示失败原因            |

Toast 只用于短暂成功反馈；需要用户处理的失败应在页面或表单附近持续显示。

## 18. 视觉设计系统

### 18.1 风格

- 克制、清晰、可信。
- 默认跟随系统 `prefers-color-scheme`；用户可在桌面端账户区域、移动端导航抽屉顶部操作区的主题菜单选择“跟随系统 / 浅色 / 深色”。手动选择以浏览器 `localStorage` 持久化并优先于系统偏好；选择“跟随系统”会清除本地覆盖并立即恢复设备主题。主题切换仅重设根节点 `data-theme` 与 `--kb-*` token，不改变 API、路由、权限或业务状态。
- 深色模式采用中性石墨底、暖白文字和低对比表面层级；保留克制的浅蓝作为交互与导航强调色，避免将整套后台染成蓝黑色。
- 内容区域以中性灰白为主，品牌色用于主要操作和导航状态。
- AI 回答与普通系统提示在视觉上区分，但不使用炫目渐变和大面积发光效果。

### 18.2 设计 token

具体色值在视觉实现时确定，必须以 CSS variables 统一管理。除颜色、间距和圆角外，控件高度、字号、行高、常用 surface、状态浅色背景、阴影、透明度与过渡也必须使用语义 token。间距统一采用 4px 网格；业务样式不得新增散落的 `8px`、`10px`、`15px` 等 gap、padding 或 margin 数字值，必须引用以下基础或语义 token。第三方组件覆盖、图形对齐和触控尺寸等确有必要的例外，须在相邻注释中说明原因。

```css
:root {
  --kb-color-primary: ...;
  --kb-color-success: ...;
  --kb-color-warning: ...;
  --kb-color-danger: ...;
  --kb-color-text-primary: ...;
  --kb-color-text-secondary: ...;
  --kb-color-border: ...;
  --kb-color-surface: ...;
  --kb-radius-sm: 6px;
  --kb-radius-md: 10px;
  --kb-radius-lg: 12px;
  --kb-opacity-hidden: 0;
  --kb-opacity-decorative: 0.2;
  --kb-opacity-disabled: 0.45;
  --kb-opacity-muted: 0.6;
  --kb-opacity-visible: 1;
  --kb-space-1: 4px;
  --kb-space-2: 8px;
  --kb-space-3: 12px;
  --kb-space-4: 16px;
  --kb-space-5: 20px;
  --kb-space-6: 24px;
  --kb-space-8: 32px;
  --kb-space-10: 40px;
  --kb-space-12: 48px;
  --kb-space-16: 64px;
  --kb-space-20: 80px;
}
```

#### 18.2.1 间距层级与断点映射

项目是桌面优先的 Web 应用。布局只使用第 23 节的 `768px` 与 `1280px` 两个断点；`375px`、`1024px`、`1440px` 与 `1920px` 是对应区间的验收宽度，不得因此新增局部媒体查询。页面外边距使用流式 `--kb-space-page`，其余组件 token 保持离散值，避免卡片和控件在相邻宽度产生不一致的密度。

| 验收宽度 / 区间      | 页面级 padding  | 页面区块 gap | 面板 padding | 元素级 gap  | 规则                                     |
| -------------------- | --------------- | ------------ | ------------ | ----------- | ---------------------------------------- |
| 375px（`<768px`）    | 12px            | 12px         | 12px         | 4/8px       | 单列，遵循移动端 12px 面板规范。         |
| 768–1279px           | 约 19px（流式） | 12px         | 12px         | 4/8/12px    | 图标侧栏，组件密度中等。                 |
| 1440px（`>=1280px`） | 约 27px（流式） | 16px         | 12px         | 4/8/12/16px | 完整桌面布局；相邻块保持紧凑。           |
| 1920px（`>=1280px`） | 约 36px（流式） | 16px         | 12px         | 4/8/12/16px | 只扩大页面留白，不放大控件和卡片内边距。 |

`--kb-space-page: clamp(12px, calc(1.8vw + 1px), 40px)` 负责页面级的连续缩放；`--kb-layout-gap`、`--kb-block-padding` 和 `--kb-list-row-padding` 在 token 文件中按既有断点覆盖。禁止以 `rem` 按视口整体缩放间距，以免浏览器文字缩放时破坏触控尺寸。

#### 18.2.2 样式归属

- `apps/web/src/styles/tokens.css` 仅声明主题、字体、控件、间距与断点 CSS 变量，不设置具体元素样式；`main.css` 只保留 reset、全局基础样式、无障碍/动效基线、页面容器、跨页面反馈、筛选、数据字段、回答来源与 Markdown 等公共结构；`element.css` 只保留对所有页面生效的 Element Plus 原生类覆盖（包括通用 Teleport 浮层），并由 `main.ts` 全局引入一次。Select、DatePicker、Dropdown 与 Tooltip 浮层共用 surface、边框、圆角、阴影及选中/悬停色基线。
- `main.css` 的公共业务 class 统一使用 `kb-*` 命名空间与 BEM：独立结构使用 `.kb-xxx`，明确依赖 Block 的内部元素使用 `__`，状态和变体使用 `--` 并与基础 Block 同时挂载。可独立复用的标题组、操作组和紧凑工具栏分别使用 `kb-title-group`、`kb-action-group` 和 `kb-control-toolbar`，不得为了形式统一强行写成其他 Block 的 Element。
- 通用内部滚动节点使用 `kb-block-scroll`；列表型滚动区叠加 `kb-block-scroll--list`，统一内容起始对齐、overscroll、列表内距与稳定 scrollbar gutter。页面 SFC 只保留行结构、选中态和业务操作样式，不重复这套滚动规则。
- 通用文字统一由 `main.css` 的两套正交体系提供：标题组合 `.kb-heading + .kb-heading--h1…h6`，正文组合 `.kb-text + .kb-text--lg/md/sm/xs + .kb-text--primary/secondary/tertiary/warning/danger/success`，字重按需追加公共 modifier。标题基础 class 只维护共同属性，层级 modifier 只维护字号、字重和行高；正文尺寸与颜色不得绑定为页面专属组合 class。业务 SFC 只保留文字布局、截断、代码字体、响应式特殊效果等页面独有规则。
- 普通文字展示不使用 `el-text`；只有确实依赖 Element Plus truncation、line-clamp 等现有公共样式无法替代的组件能力时才允许保留。模板按当前产品约束不使用 `p` 或 `h1`–`h6`：块级文字使用 `div`，行内文字使用 `span`，标题使用带 `role="heading"` / `aria-level` 的 `div` 或 `span`，HTML 语义与 `kb-heading*` / `kb-text*` 视觉层级相互独立。
- Element Plus 2.14.3 的 light/dark theme 均优先通过官方 `--el-*` 变量映射现有 `--kb-*` token。根级 `ElConfigProvider` 三端固定使用 `size="default"`；`element.css` 将 default / large / small 的 Button、Input、Select、DatePicker、InputNumber、Pagination、Tabs、Dropdown、Collapse、Upload 和弹层关闭按钮外框统一到 `--kb-control-height`，并同步覆盖 padding、字号、圆角和图标 gap。页面 `kb-block` 公共容器使用 `--kb-radius-lg`，普通 Element 控件使用 `--kb-radius-md`；pill、circle、Tag 与 bottom sheet 等明确语义形状继续使用各自圆角 token。`tokens.css` 为浅色、显式深色和系统深色完整重设全部颜色与阴影 token；Markdown 代码块、原始/脱敏分块对比和加载遮罩使用语义 token，不在页面中另建主题色表。
- Element Plus 的 Pagination、DatePicker、TimePicker 等内置文案由根级 `ElConfigProvider` 统一提供简体中文 locale，业务页不得分别覆写语言。
- Filled Primary Button 的 default 边框使用 `--kb-color-brand-highlight`，hover 与 active 使用 `--kb-color-primary`，避免边框与填充同色造成视觉尺寸大于同高的默认按钮，同时避免深色硬描边；不得通过缩小 Primary 的高度或 padding 补偿视觉误差。
- Filled Danger Button 与 Primary 使用相同色阶机制：默认态使用 `--kb-color-danger`，hover 使用由 danger 与 surface 派生的 `--kb-color-danger-highlight`，文字继续使用 `--kb-color-on-primary`；`danger-soft` 只用于浅状态背景，不作为 filled hover。
- Primary 可以使用现有 dark、base、brand highlight、nav accent 与 soft token 形成近似阶梯；Danger 已补充由 base 与 surface 派生的 highlight，供 filled hover 使用，其他浅档仍映射 soft。Success、warning 和 info 目前只有 base / soft 两档，Element 的 `light-3/5/7/8/9` 暂时合并映射。若后续视觉要求这些状态的 hover、plain、disabled 与浅背景有可辨层级，应先在 token 体系补齐正式色阶，再更新映射，禁止在 `element.css` 临时生成或硬编码中间色。
- 所有同层级块级容器统一使用 `kb-block` 提供 padding、边框、圆角、背景与无阴影 surface；业务语义 class 仅用于内容和布局定位，不得再次承载基础视觉。共享差异使用 `kb-block--compact`、`kb-block--spacious`、`kb-block--flush` 或 `kb-block--interactive` modifier，响应式只调整布局、列数或位置，不重新定义基础视觉和 Element Plus 控件尺寸。
- 文件名、查看全部、任务标识和复制 ID 等文字型可点击入口统一使用 `<el-link class="kb-link" type="primary" underline="never">`，文字放入 `kb-link__text` 以共享左对齐、安全收缩与省略；占满可用宽度使用 `kb-link--fill`，明确的右对齐值使用 `kb-link--end`。内部路由使用 `RouterLink custom` 向 `el-link` 传入 `href` 和 `navigate`，不得用默认 `RouterLink` 在 `el-link` 外层生成嵌套锚点。主要按钮、品牌、侧栏导航、整行/整卡和移动菜单项保留各自原有交互容器语义。
- `--kb-shadow-input` 专用于 `AskComposer` 的输入区域，以高于通用 `--kb-shadow-subtle` 的可见阴影将可交互问答区从页面背景中托起；不得将其扩展为卡片、表格或普通 Element 控件的通用阴影。
- 字段卡片列表统一使用 `kb-block-list`、`kb-block__header/title`、`kb-data-fields` 和 `kb-data-field__label/value`；不需要字段分隔线时追加 `kb-data-fields--borderless`，不得在页面内重写整套字段行。`kb-data-field__label/value` 同时承担该结构稳定的字号、行高和主/次文字色；label 使用内容宽度、不参与 Flex 收缩且固定单行，value 承担剩余宽度的收缩和安全换行。业务模板只在确有强调、警告或特殊尺寸时追加 `kb-text--*` modifier，不重复组合基线文字 class。它们可用于手机表格替代、详情字段和 Provider 摘要。不得新增或继续使用按设备命名的 `mobile-data-*` / `mobile-field-*` class。
- 表格展开详情和任务摘要等“标签在上、值在下”的紧凑数据块统一使用 `kb-data-grid`、`kb-data-grid__item` 与 `kb-data-grid__value`；三、四、五列分别使用 `kb-data-grid--three` / `kb-data-grid--four` / `kb-data-grid--five`，五列在 Pad 收为三列，Mobile 全部收为两列。标签直接组合 `kb-text*`；`kb-data-grid__value` 承担稳定的值文字基线（主文字色、正文字号、紧凑行高与中等字重），业务模板只在确有状态或特殊尺寸时追加 modifier；数据网格不自行添加 border、border-radius 或 background。需要由子项或外层容器提供内距时追加 `kb-data-grid--flush`。审计展开、入库任务、系统摘要/队列与用量摘要直接组合上述共享 class，不再为页面名称、对称命名或 E2E 定位保留无样式业务 alias。系统与用量摘要父网格使用 `kb-data-grid--flush`，三个直接子项分别挂载 `kb-block`；任务与队列网格同样使用 `kb-data-grid--flush` 将 padding 设为 0，队列由外层 `kb-block` 提供容器边界。
- 双栏目录/详情布局统一复用 `kb-split-layout`，同构状态工具栏统一复用 `kb-status-toolbar`，跨页面整块错误与保留内容后的行内错误分别使用 `kb-error-state` 和 `kb-inline-error`。`main.css` 公共交互状态统一使用对应 Block 的 `--` modifier；组件 scoped CSS 内只服务于本组件的瞬时状态可继续使用 `is-*`，不得使用无语义的 `active`、`empty` 或 `danger`。
- `kb-error-state` 自身完整提供统一的 danger-soft 背景、边框、圆角、内边距和标题字重，不依赖是否位于 `kb-block` 内。错误标题使用 `kb-text--danger` 且固定为 600 字重；页面不得为同一类错误另写背景或字重。
- Dialog 与 Drawer 的默认 Close 统一使用带边框的圆形外框、同一控件高度、图标尺寸与 hover/focus/active 反馈，由 `element.css` 同时维护 `.el-dialog__headerbtn` 和 `.el-drawer__close-btn`。三种状态的边框都保持中性色，hover/focus 使用 primary-soft 背景，active 使用 nav-accent 背景，不使用蓝色边框表达交互。自定义 Drawer 标题栏如果必须自带 Close，也必须对齐该边框、尺寸和交互态。
- `el-message-box` 与标准 `el-dialog` 使用同一 `--kb-radius-md` 圆角，确认弹层不得保留 Element Plus 默认的更小圆角。
- 页面、布局和业务组件的样式必须与对应 `.vue` 文件放在一起，并使用 `<style scoped>`；形如 `.xxx-form .el-*`、`.xxx-table .el-*` 的页面专属覆盖不得进入 `element.css`。业务 SFC 应优先直接样式化挂到 Element 组件上的业务 class；只有必须命中第三方组件内部 DOM 时，才允许在业务根 class 下使用范围最小的 `:deep()`，不得使用 `:global()`。同一 Element 变体已在多个页面以相同语义复用时，才将语义 class 直接挂到组件或 `popper-class` 上，并由 `element.css` 统一维护。
- 只有已经在多个页面以同一结构、同一交互语义稳定复用的模式才可抽到 `main.css`；页面专属选择器必须留在对应 `.vue` 文件，不得为减少行数而将它们重新放回全局样式。
- 业务样式统一使用能表达“父容器语义 + 元素用途”的 class 选择器，不以 `strong`、`span`、`ul`、`li`、`header` 等原生标签作为样式定位条件；模板保留原生标签语义，只追加 class。动态生成的 Markdown 节点和依赖 DOM 查询的脚本必须使用同一组语义 class。全局 reset/base 与受控的第三方组件内部样式不受此条限制。

#### 18.2.2 gap、padding 与 margin 使用边界

- `gap`：仅用于 Flex/Grid 子项之间的关系。元素级使用 `--kb-space-inline`（8px）或 `--kb-space-element`（12px）；组件内部使用 `--kb-space-component`（16px）；工具栏、相邻面板和页面区块优先使用 `--kb-layout-gap`（PC 16px，Pad/Mobile 12px）。不以子项 margin 模拟列表间距。
- `padding`：用于容器边界到内容的内距。页面壳使用 `--kb-space-page-block var(--kb-space-page)`；块级容器、工具栏和内容面板优先使用 `--kb-block-padding`（12px）；紧凑列表行优先使用 `--kb-list-row-padding`（12px）。业务样式只在确实属于基础间距、而非上述布局语义时直接引用 `--kb-space-3`。交互控件仍需满足既有 44px 最小触控高度，不应单靠减小 padding 压缩。
- `margin`：只用于组件与外部文档流的关系，或文字段落的语义间隔；同级布局间距一律由父容器的 `gap` 管理。禁止同时为父容器设置 `gap`、又为其直接子项设置同方向 margin。页面首尾留白由页面容器 padding 提供，标题不承担定位留白。
- Element Plus 相邻按钮统一覆盖为 `.el-button + .el-button { margin-left: 0; }`；工具栏、表格行操作、Dialog/Drawer footer 和移动筛选操作组必须由各自 Flex/Grid 父容器显式设置 `gap`。PC、Pad、Mobile 不得同时叠加父级 `gap` 与按钮左外边距，也不得依赖隐式相邻 margin 维持按钮间距。

### 18.3 信息密度

- 表格默认中等密度，允许用户切换紧凑模式。
- 正文行宽控制在可读范围。
- 问答正文使用 16px 左右基础字号和舒适行高。
- 次要 metadata 降低视觉权重，但不能低到影响可读性。

### 18.4 状态颜色

- 成功：已生效、完成。
- 警告：策略阻止、部分成功、需要关注。
- 错误：失败、无权限、危险操作。
- 信息：排队、处理中。

颜色必须搭配文字、图标或形状，满足色觉障碍用户。

## 20. API 对接

认证方式、capability/ACL、完整端点目录、错误码、分页和安全调用示例见 [07-API使用说明.md](./07-API使用说明.md)。前端仍以共享 Zod 契约和 `packages/contracts/openapi/api.v1.yaml` 为字段事实源，不从本文手工复制响应类型。

### 20.1 接口使用原则

按业务域在 `src/api` 封装请求，端点和字段直接以 OpenAPI/Zod 契约为准，不在本文维护第二份映射表。知识问答仅发送 `question`，继续当前会话时可附带服务端签发的 `conversationId`；不能发送 tenant、role、department、任意 Chroma where、历史正文或敏感度覆盖值。429 保留输入并提示稍后重试；响应来源按 `index` 对应正文中的 `[来源N]`，只渲染本次响应返回的来源。

### 20.2 请求封装

- 统一 base URL、credentials、超时和错误映射。
- 自动透传/接收 trace ID。
- 401 统一进入重新认证流程。
- 403 不自动跳登录，显示无权限。
- GET 可按数据类型缓存；权限敏感详情不长期缓存。
- mutation 成功后精确失效相关查询，不做全局粗暴刷新。
- 不对非幂等请求自动无限重试。

### 20.3 实时进度

当前使用轮询查询 ingestion job；轮询采用退避并在页面不可见时降低频率。任务量增加后再评估 SSE/WebSocket。

不要为了进度条提前引入实时连接复杂度。

`converting` 是服务端持久化的真实任务状态。轮询期间使用不确定进度条；只有后端未来提供可验证的转换进度字段后，才允许切换为确定百分比进度条。

## 22. 路由与权限实现

```ts
declare module 'vue-router' {
  interface RouteMeta {
    requiresAuth?: boolean;
    capabilities?: string[];
    title?: string;
  }
}
```

- 全局 guard 检查登录状态和已加载的 capability。
- 首次加载身份期间显示应用级 skeleton，避免先闪现无权限页面。
- capability 不满足时进入 `/403`。
- `adminOnly` 路由在角色不是 `admin` 时进入 `/403`，即使身份意外携带管理 capability 也不展示或放行管理页。
- API 返回 403 时仍以服务端为准，不能因为前端 capability 判断通过就忽略。
- 页面标题随路由更新。
- 登出后清理内存 store、query cache 和敏感页面状态。

## 23. 响应式设计

### 23.1 唯一断点与实现边界（2026-08-13）

全项目仅使用以下断点，不得在页面或组件中新增 `matchMedia`、`window.innerWidth` 或其他自定义阈值：

| 断点     | 范围         | 布局规则                                 |
| -------- | ------------ | ---------------------------------------- |
| `1280px` | `>= 1280px`  | 完整分组侧栏、会话列表和右侧来源抽屉     |
| `768px`  | `768–1279px` | 图标侧栏、紧凑内容布局                   |
| `767px`  | `<768px`     | 左侧可展开 sidebar；单列和 44px 触控布局 |

`apps/web/src/styles/breakpoints.scss` 记录唯一的断点数值与语义；`main.css`、`tokens.css` 中的 `@media` 只能使用上表的 `767/768/1279/1280px` 边界组合，不得引入新的视口阈值。Vue 结构分支必须通过 `useBreakpoint()` 的 `isDesktop`、`isTablet`、`isMobile`、`isCompact` 读取。禁止用 CSS `display: none` 同时保留桌面表格和移动端卡片 DOM。列表数据只获取一次，再通过 `v-if` 在桌面表格与移动端卡片组件之间切换。

不新增视口断点的前提下，受侧栏影响的详情操作区与信息卡必须使用 `flex-wrap`、`minmax()` 或 `auto-fit` 按**实际可用内容宽度**连续重排；浏览器拖动缩放时不得等到下一个全局断点才处理溢出。

移动端通用替换规则：

- 文档管理与入库任务在 `<1280px` 使用字段取舍后的卡片列表；审计、用户、Provider 和用量页在手机使用卡片列表，Pad 保留可横向滚动的紧凑表格并隐藏次要列。
- 横向筛选表单默认替换为使用统一 `kb-filter-trigger` 的“筛选”按钮和 `direction="btt"` 的筛选 Drawer；筛选与重置放在同一操作组。文档管理、入库任务与用户目录均在 Drawer 内存在非空条件时为触发按钮添加 `is-active`，统一使用 `kb-filter-trigger--active::after` 圆点与主色边框/文字；重置后同步取消。问答历史的内联筛选/重置和审计中心的内联 Select/重置是明确例外。
- 右侧详情 Drawer 在 `<768px` 使用 `size="100%"`；居中 Dialog 在手机使用底部 Drawer 或全屏 Drawer。
- 危险操作仍必须明确影响范围并要求输入文档名确认；手机端不可降级为普通“确定”。
- 所有 Drawer/Dialog 通过 Teleport 挂到 `body`，顶栏高度 56px，遮罩覆盖应用壳层。
- 所有 `el-drawer` 复用 `element.css` 中的统一视觉壳层：白色面板、统一阴影、56px 标题栏、标题字号、圆形关闭按钮、正文内边距以及带安全区的 footer；底部 Drawer 统一使用 18px 顶部圆角和居中的拖拽把手。业务组件不得重复绘制把手、标题栏、关闭按钮、边框或背景，只能按用途调整方向、尺寸和内容区布局。
- Element Plus 的全局浮层基线为 `5000`；移动端 Drawer 内的 Select、DatePicker 等 `el-popper` 必须高于 Drawer 与遮罩，禁止页面单独设置冲突的 popper 层级。
- 通过脚本动态切换的 `ElDialog/ElDrawer` 必须显式引入两者的基础 CSS；弹框正文负责短视口滚动，header/footer 保持可见，不能依赖自动组件解析器间接加载样式。
- 文档权限 metadata 编辑在桌面使用标准 Dialog，在手机使用 `direction="btt"` 且内容自适应高度的底部 Drawer；两端分支分别挂载，保证表单、页脚和焦点管理稳定。

P0/P1 额外规则：问答输入框保留安全区底部间距；上传 Drawer 隐藏拖放提示且文件列表独立滚动；入库步骤条在 `<768px` 垂直显示；文档详情操作在手机统一收进右上角“⋯”触发的底部操作面板，操作项使用统一移动操作面板的图标、文字、右侧箭头、卡片背景、边框与圆角，关闭按钮使用同一 `Close` 图标，删除项保持红色；审计卡片默认折叠 Trace ID；用户与托管角色仍在展开卡片中触发编辑，Mobile 统一以底部 Drawer 承载表单；部门敏感度策略保持卡片内联编辑。信息区的 `el-descriptions` 在移动端固定单列。

本项目桌面优先，但所有已授权页面都必须在移动端保持可用：

- `>=1280px`：完整侧栏、会话列表和右侧来源抽屉。
- `768–1279px`：图标侧栏，来源抽屉覆盖内容；文档/任务使用卡片，系统配置表单改为单栏。
- `<768px`：顶部汉堡按钮从左侧展开与 PC 同分组的 sidebar，保留当前身份可访问的全部入口（包括 Provider、用量与系统状态）；页面保持完整可用视口高度，不为菜单预留底部空间。筛选栏、Provider、系统状态、权限和用量页面均须适配单列布局，主要触控控件最小高度为 44px。

移动端不能让页面整体横向滚动：

- 桌面/平板：表格的横向滚动仅限各自内容块，表头及固定列在该块内保持可见。
- 手机：表格改为带字段标签的信息卡片列表，不让用户在窄屏横向拖动表格。
- 可滚动列表的标题或固定项在该块内保持可见。
- 日期范围控件、Provider 详情及用量卡片不得突破容器。
- 主要操作固定在可达区域。
- 对话输入框适配软键盘。
- 来源详情改为带全视口遮罩的底部 bottom sheet，保留拖拽把手视觉以及遮罩、右上角按钮关闭方式，不切换路由。
- 弹框与 Drawer 遮罩必须覆盖应用侧栏和顶部壳层；Drawer 顶栏与应用顶栏统一为 56px。
- 弹框通过全局 Teleport 挂载到 `body`；宽度不得超过 `100vw - 28px`，正文在可视高度内独立滚动。
- `768–1279px` 的文档筛选区采用可换行 Grid；筛选和重置保持同一操作组，不各自占用一整行。所有筛选提交操作统一命名为“筛选”，不得与“查询”或“应用”混用。
- 信息展示优先使用 `el-descriptions` 或 `div + Flex/Grid` 字段单元；避免以 `dl/dt/dd` 承担页面布局。表单优先使用 Element Plus 控件并保留 `form`、`label`、`button` 等必要语义。
- 展示性段落与列表统一使用 `div + class`，包括受控 Markdown 的段落和列表输出；不在移动端依赖 `p`、`dl/dt/dd`、`ul/li` 的浏览器默认排版。交互与表单优先使用 Element Plus 组件，问答多行输入使用 `el-input type="textarea"`。
- 页面与受控 Markdown 的标题同样统一使用带层级 class 的 `div`；页面一级标题组合 `kb-heading kb-heading--h1`，通过 `role="heading"` 与 `aria-level` 保留标题导航语义。项目模板不使用 `p` 或 `h1`–`h6`；视觉层级不得通过改换标签、私有字号或 `el-text` 实现。
- 在 `<768px`，所有可聚焦的 Element Plus 输入、选择与日期输入文本保持至少 `16px` 字号，避免 iOS 聚焦时触发页面自动缩放；不得通过禁用用户缩放来替代该规则。
- Element Plus 表单与操作控件在 PC、Pad、Mobile 均使用 `--kb-control-height` 对应的默认高度；`size="large"` 或 `size="small"` 只保留组件的语义和内部实现兼容性，不改变全局控件外框高度。移动端触控可达性通过工具栏间距、整行操作区和容器布局保证，不再单独放大 Element 控件高度。
- 用量页三端统一使用一个 `el-date-picker type="daterange" single-panel`。日期控件设置 `editable=false`，只允许通过日历选择日，避免手机唤起输入法；PC 与 Pad 保留筛选/重置，并与 `audit-filter-form` 一样使用 Flex 紧凑排列，DatePicker 恢复 Element Plus 的 daterange 标准宽度，不占满整行。Mobile 选完范围后立即应用并保留重置，不使用筛选 Drawer；DatePicker 填满重置按钮之外的可收缩列且不得沿 X 轴溢出。日期选择浮层使用 `bottom-start` 和受控 Popper modifier 与触发器等宽、左侧对齐，同时限制在手机安全视口内并 Teleport 到全局浮层；三端的单面板根节点、body-wrapper、body 与 content 均为 Popper 的 `100%` 宽度，清除内部默认 `322px` 最小宽度，并以 content 内部 padding 保留日历留白。
- 审计、用户目录与用量的筛选型顶部控制统一使用无外壳 `xxxx-toolbar`，保持 40px 控件高度和相同 gap；Provider 和系统状态等状态型 toolbar 可保留必要的面板与说明。用户目录和用量页不在工具栏重复页面标题或长说明，直接采用第 6.2 节定义的三端筛选布局。Mobile 的任务、审计、Provider、系统状态和用量工具栏保持紧凑单行，主要操作保留在右侧。
- 移动端页面区块使用统一的 `12px` 间距与 `12px` 内边距 token；问答历史使用“会话列表 → 全宽详情”的两级结构，同一时刻不并排或上下同时挂载两级内容。桌面与 Pad 的 `history-layout` 必须占满筛选栏以下的可用高度，左侧列表与右侧详情各自在面板内滚动。会话行触控高度不低于 `72px`，左滑露出的删除入口触控宽度不低于 `48px`。
- 横屏手机（`<768px` 且高度 `<=500px`）属于低高度移动端：应用顶栏保持紧凑，侧向 sidebar 继续按需展开且不占正文高度，页面分类与说明隐藏，正文优先保留独立滚动区；用户目录和部门权限由各自内容容器滚动，历史、审计、用量与系统类工具栏收敛为单行右侧筛选/刷新操作。历史页仍保持列表/详情两级结构，不因横屏恢复双栏；文档详情和移动端信息卡允许双列，禁止横向溢出。

当前验收重点为桌面端 1440px 和常见笔记本宽度 1280px，同时保证 768px 不出现不可操作布局。

## 25. 前端安全

- 不在浏览器中调用模型供应商 API。
- 不在前端构建时注入模型 API Key。
- 不信任路由参数、文件名、Markdown 和模型回答。
- 实时与历史模型回答统一使用 `markdown-it`（原始 HTML、自动链接关闭）解析，再经 `DOMPurify` 标签、属性和 URI 协议白名单清洗；禁止直接渲染未经清洗的 HTML。
- `SafeMarkdown` 支持 `\\[...\\]`、`$$...$$` 块公式及 `\\(...\\)`、`$...$` 行内公式，也兼容 `[\\ ... \\]` 的模型输出变体；围栏代码块始终保持字面代码。若模型留下一段未闭合围栏且紧接内容以块公式开始，组件只移除该无效围栏并修复相邻的重复 `$$`，使历史回答不会整体落入 `pre`。KaTeX 仅在浏览器本地渲染，固定关闭 trust 扩展并限制扩展次数和尺寸。公式生成的 MathML、class 与布局 style 可经专用白名单保留，源 Markdown 的 HTML 和 style 仍不被解析。
- Markdown 链接只允许 `http`、`https`、`mailto` 和站内相对地址，拒绝协议相对 URL；外部链接增加 `target="_blank"` 和 `rel="noopener noreferrer"`。
- Markdown 图片和其他可发起隐式网络请求的嵌入内容不渲染，避免跟踪像素和越权资源加载。
- 不执行回答或文档中的脚本、iframe 和事件属性。
- 上传文件仍由后端完整校验。
- CSRF、CORS 和 Cookie 策略由前后端联合设计。
- 退出登录清理内存中的权限敏感数据。
- 错误监控在发送前移除问题正文、回答、文档名和 token。
- Provider 密钥输入禁止被通用表单回放、analytics 或 session replay 采集。
