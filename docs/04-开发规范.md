## 2. 通用工程原则

### 2.1 优先级

1. 安全和租户隔离。
2. 数据正确性和可恢复性。
3. 清晰、可测试和可维护性。
4. 用户体验和性能。
5. 开发便利性。

不得为了少写代码而降低权限、审计、幂等或错误处理要求。

### 2.2 代码原则

- 保持模块职责单一。
- 优先使用小而明确的接口，不建立万能 service。
- 业务逻辑不放在 controller、Vue 页面组件或基础设施 adapter 中。
- 外部输入必须运行时校验。
- 显式处理失败，不吞异常。
- 避免全局可变状态和隐式副作用。
- 重要算法和安全决策说明“为什么”，不要用注释重复代码。
- 不为未知需求提前构建复杂抽象。
- 删除无用代码，不长期保留注释掉的旧实现。
- 不复制粘贴形成两套近似业务流程。

### 2.3 语言

- 代码标识符使用英文。
- 用户界面和面向用户的错误信息使用简体中文，预留国际化能力。
- Git commit 可使用中文或英文，但仓库内保持统一。
- 技术文档以中文为主，必要的标准名词保留英文。

## 3. 仓库与目录

```text
apps/
├── web/                    Vue 3 前端
├── api/                    NestJS 主服务
└── parser-worker/          Python 解析 Worker
packages/
├── contracts/              DTO、事件和生成契约
└── config/                 可共享的开发配置
docs/                       项目文档
```

规则：

- 业务代码只能放入对应 app/module。
- `packages/contracts` 不依赖具体 UI、数据库或 Provider SDK。
- 不从一个 app 直接引用另一个 app 的内部源码。
- 跨服务通过契约或公开 package 通信。
- 测试 fixture 放在明确的 `test/fixtures`，不得混入生产数据目录。
- 上传文件、向量数据、数据库文件和日志不得进入 Git。

## 4. TypeScript 通用规范

### 4.1 编译与类型

- 开启 `strict`。
- 禁止无说明的 `any`；外部未知数据先使用 `unknown`，验证后再缩窄。
- 禁止使用 `@ts-ignore` 隐藏问题；确有必要时使用带原因的 `@ts-expect-error`。
- 公共函数、Provider 接口和 DTO 使用明确类型。
- 避免不安全的非空断言 `!`。
- 优先使用判别联合表达状态，而不是多个可能冲突的 boolean。

推荐：

```ts
type IngestionState =
  | { status: 'queued' }
  | { status: 'processing'; step: IngestionStep; progress: number }
  | { status: 'completed'; documentVersion: number }
  | { status: 'failed'; errorCode: string; retryable: boolean };
```

不推荐：

```ts
interface State {
  loading: boolean;
  completed: boolean;
  failed: boolean;
}
```

### 4.2 命名

- 类型、类、Vue 组件：PascalCase。
- 函数、变量、composable：camelCase。
- 常量：对真正全局不可变值使用 UPPER_SNAKE_CASE。
- 文件名遵循各框架惯例，项目内保持一致。
- boolean 以 `is`、`has`、`can`、`should` 开头。
- 集合使用复数名。
- 不使用含义不明的 `data`、`info`、`item` 作为跨越大作用域的名称。

### 4.3 异步代码

- 使用 `async/await`，避免无必要的 Promise 链嵌套。
- 所有外部请求设置超时。
- 并发批次必须有上限，不能对大数组直接无限 `Promise.all`。
- 不创建未处理的 floating Promise。
- 取消、超时和重试必须区分。
- 非幂等操作不自动无限重试。

### 4.4 格式和静态检查

- 使用统一 ESLint 和 Prettier 配置。
- Markdown 修改必须通过 `pnpm docs:check`；该命令检查 Prettier、本地链接/锚点、API 文档与 OpenAPI 的端点目录、Rerank Provider 目录和前端视口断点的一致性，并由根目录 `pnpm lint` 在 CI 中执行。
- CSS、SCSS 和 Vue SFC 的样式声明使用根目录 `stylelint.config.cjs` 定义的语义分组顺序； `pnpm format:css` 自动修复，`pnpm lint:css` 只检查不修改。分组之间不插入空行，未列出的属性统一置于末尾并按字母排序。
- 页面与业务组件的区块间距、列表行内距和块内距分别优先使用 `--kb-layout-gap`、`--kb-list-row-padding`、`--kb-block-padding`；除 token 定义或确实不属于上述布局语义的元素级间距外，避免直接引用 `--kb-space-3`。
- `opacity` 必须引用 `tokens.css` 中的 `--kb-opacity-*` 语义档位，不得在 CSS、SCSS 或 Vue SFC 中直接写 `0`、`0.x`、`1` 等裸数字；Stylelint 对此强制校验。
- VS Code / Cursor 使用工作区推荐的 Stylelint 扩展，并通过 `.vscode/settings.json` 在保存 CSS、SCSS 或 Vue 文件时自动修复声明顺序。
- VS Code / Cursor 使用工作区推荐的 Prettier 扩展，在保存 JSON、JSONC 和 Vue 文件时自动格式化。
- 不在局部目录创建相互冲突的格式配置。
- 提交前必须通过 lint、typecheck、test 和 build。
- CI 还必须独立执行 Stylelint、Web Playwright、Parser/Reranker 的 Ruff/Mypy/pytest，以及生产 API/Web/Parser/Reranker/deployment-agent/PostgreSQL/Redis/Chroma/Tika 镜像构建、Trivy 高危漏洞门禁和 CycloneDX SBOM 产出。含授权 ODA 的 DWG 镜像由受控发布环境执行同等构建、扫描和 digest 固定，不能把授权包放入 GitHub artifact。
- Trivy 门禁只扫描漏洞（`scanners=vuln`），`HIGH`/`CRITICAL` 且已有修复的结果必须失败关闭。优先升级应用依赖、基础镜像或重建内嵌二进制；不得通过降低 severity、改为 `exit-code=0` 或全局 CVE 忽略让 CI 变绿。上游尚未发布可用修复时，`.trivyignore.yaml` 例外必须同时限定到精确镜像内路径、记录不可利用或隔离依据并设置不超过一个月的 `expired_at`；到期后 CI 自动重新失败，发布前必须复核、升级或重新批准，禁止无期限续写。
- `pnpm test:parser` 必须使用 `docker compose run --build`，确保挂载的新测试始终匹配当前 Worker 源码镜像；禁止用旧镜像运行新测试后把收集错误误判为代码失败。
- 禁止通过大范围 disable 关闭 lint 规则。

## 5. Vue 前端规范

### 5.1 组件

- 使用 Vue 3 Composition API 和 `<script setup lang="ts">`。
- 页面组件负责组合，复杂业务逻辑下沉 composable/service。
- 通用组件不直接访问路由、Pinia 或具体业务 API，除非组件职责明确要求。
- 页面 SFC 的 `<style scoped>` 中，页面独有 class 必须使用由文件名语义导出的 kebab-case 前缀：`AuditView.vue` 使用 `audit-*`，`ProviderSettingsView.vue` 使用 `provider-*`，避免 `card`、`toolbar`、`detail` 等跨页面含义不明确的裸前缀。`kb-*` 公共 class、Element Plus `el-*` class 和功能子组件自身的封装 class 不受此限制；子组件不得借用父页面的 class 前缀。
- 静态 `class` 属性按“页面或组件私有 class、公共结构 class、`kb-heading` / `kb-text` 基类、modifier 与状态 class”排列；同类节点使用相同顺序，不因搬迁或重命名改变组合顺序。
- `apps/web/src/components/` 只存放跨功能复用的 Vue 公共组件，文件名使用与组件一致的 PascalCase。一级导航页面直接放在 `views/` 根目录；文档详情、预览和分块等功能二级路由页面，以及只服务于某个页面的子 Vue，可以放入 `views/<feature>/`。页面私有子组件以所属页面名开头（例如 `DocumentsPreviewTileViewer.vue`），对应测试也使用完整组件名。由同一功能域的多个页面共享、但不跨功能复用的子组件使用功能域前缀。类型、纯函数和其他非 Vue 实现细节不得留在 `components/`，应放入 `utils/`、`composables/` 或所属功能目录。功能私有组件一旦被其他功能域引用，才提升至 `components/` 并使用独立语义名称。
- props 和 emits 必须有类型。
- 双向绑定只用于真正的表单状态，避免跨层级隐式修改。
- 一个组件过大或同时承担数据获取、权限、布局和复杂交互时必须拆分。
- 一级菜单页面继续使用动态 import 分包；不得在应用壳层登录后后台下载全部可见页面模块。开发模式的冷启动整页 reload 必须从 Vite 依赖优化与样式入口修复，不得用运行时页面预加载掩盖。
- Element Plus resolver 只负责按需导入组件 JavaScript，固定使用 `importStyle: false`；官方完整 CSS 在前端入口一次引入，并由本项目全局样式在其后覆盖。不得恢复逐组件 `style/css` 自动注入，否则 Vite 冷启动会在首次访问懒加载菜单时逐批优化依赖并强制 reload。
- 文字型可点击入口使用 `<el-link class="kb-link" type="primary" underline="never">`，实际文字使用 `kb-link__text`；需要填满容器或右对齐时分别追加 `kb-link--fill` / `kb-link--end`，不得在页面重写 `.el-link__inner`。内部路由必须使用 `RouterLink custom` 提供 `href` / `navigate`，由 `el-link` 渲染唯一锚点；禁止使用默认 `RouterLink` 包裹 `el-link` 形成嵌套 `<a>`。按钮操作、整行/整卡导航与主导航不得为了外观统一而降级为文字链接。
- `main.css` 公共业务 class 必须使用 `kb-*` 命名空间和 BEM。`__` 只表示明确依赖父 Block 的 Element，`--` 只表示状态或变体并与基础 Block 同时挂载；能跨父容器独立复用的结构使用独立 Block，不得为了形式统一强行嵌套。重命名公共 class 时必须同步 Vue、动态生成 DOM、单元测试和 E2E 定位，不保留旧名兼容层。
- 通用标题必须组合 `.kb-heading` 与一个 `.kb-heading--h1` 至 `.kb-heading--h6` 视觉层级；通用文字必须组合 `.kb-text`、一个尺寸 modifier 与按需的颜色/字重 modifier。尺寸只负责字号与行高，颜色只负责文字颜色，不创建“某页面说明文字”之类组合 class。项目模板不使用 `p` 或 `h1`–`h6`，展示性块级/行内文字分别使用 `div` / `span`；标题以 `role="heading"` 和 `aria-level` 保留层级语义。普通文字不得仅为字号、颜色或字重使用 `el-text`，只有确实依赖其 truncation / line-clamp 等组件能力时才保留。
- 紧凑的纵向“标签 + 值”数据网格使用 `kb-data-grid`、`kb-data-grid__item` 与 `kb-data-grid__value`，列数使用 `kb-data-grid--three` / `kb-data-grid--four` / `kb-data-grid--five`，padding 需要归零时使用 `kb-data-grid--flush`。标签无独立布局职责，直接组合 `kb-text*` 公共文字 class；`kb-data-grid__value` 封装值的稳定字号、行高、颜色与字重，只在状态或尺寸确有差异时叠加文字 modifier。不得为测试定位或对称命名单独增加业务 alias，不得在业务 SFC 重复定义该结构的 Grid、padding、字号、颜色或响应式列数。水平“标签 + 值”字段行继续使用 `kb-data-fields` / `kb-data-field*`；`kb-data-field__label/value` 封装该结构稳定的文字基线，只在状态或强调确有差异时叠加文字 modifier，两种数据结构不混用。

### 5.2 状态

- Pinia 保存身份摘要、导航和界面偏好。
- 服务端数据由 query/composable 层管理。
- 不把 API 响应无差别复制进全局 store。
- 不在 `localStorage` 保存完整问答、来源片段、API Key 或权限敏感数据。
- 登出时清空身份、query cache 和敏感页面状态。

### 5.3 路由与权限

- 使用 Vue Router route meta 声明认证和 capability。
- 管理页面还必须声明管理员角色门槛；普通用户仅可访问知识问答和个人问答历史。
- route guard 只负责前端体验，不替代后端鉴权。
- API 返回 403 时显示无权限，不自动当作未登录。
- 未登录与无权限必须区分。
- 页面刷新后重新加载服务端身份，不能只信任浏览器缓存角色。
- 账号密码表单只可提交到同源认证 API；密码在成功或失败后立即清空，禁止写入 Pinia、localStorage、URL、日志、analytics、错误监控或 session replay。浏览器会话仅依赖服务端签发的 HttpOnly Cookie。

### 5.4 表单

- 所有字段有 label、验证状态和可操作错误信息。
- 前端验证用于即时反馈，后端仍完整验证。
- 防止重复提交，mutation 使用 client request ID 或幂等机制。
- 危险操作明确展示影响对象和范围。
- Provider 密钥提交后立即清空，不回显现有值。

### 5.5 内容安全

- 模型回答和文档片段默认作为文本或受控 Markdown 渲染。
- 禁止 `v-html` 渲染未经严格清洗的模型或文档内容。
- 受控 Markdown 必须复用统一组件：解析器关闭原始 HTML，输出再经过标签、属性和 URI 协议白名单清洗；不允许页面各自实现正则替换或独立放宽规则。
- 若受控 Markdown 渲染 TeX，必须使用统一的本地 KaTeX 配置，关闭 trust 扩展并限制扩展次数和尺寸；只允许其生成的 MathML、class 和布局 style，通过最终清洗白名单后输出，不能放宽源 Markdown 的 HTML 或 style。
- 可修复模型产生的明确 Markdown 格式错误，但规则必须语义收敛且有回归测试；例如仅移除“未闭合且紧随块公式”的围栏，不得把合法代码块或任意 TeX 片段转换为公式。
- 外部链接只允许批准的安全协议，并增加 `noopener noreferrer`；图片、iframe、SVG、表单和其他隐式加载或可执行嵌入默认禁止。
- 不执行回答中的脚本、iframe、事件属性和嵌入组件。
- 错误监控和 analytics 不采集问题正文、回答、文档片段和密钥输入。
- 混合回答必须通过契约字段区分 `grounded` 与 `general`，不能根据“是否看起来像通用知识”由前端猜测。
- 通用回答只允许空 contexts，必须经过问题敏感度出网策略；权限变化、confidential 阻止和 Provider 错误不得静默伪装成成功的通用回答。
- 正式 RAG 质量评测必须使用严格回答模式，避免通用知识回答污染 Recall、引用和无答案拒答指标。
- 上线质量门禁必须对 baseline 与所有候选策略分别强制 `unauthorizedLeakRate=0`；候选策略即使最终建议保持关闭，只要曾召回、重排或引用未授权来源，评测命令仍必须失败关闭并作为安全事件处理。

### 5.6 可访问性

- 图标按钮必须有可访问名称。
- 弹窗正确管理焦点。
- 表单错误与字段关联。
- 状态不能只依赖颜色。
- 核心流程支持键盘。
- 尊重 reduced motion。
- 对比度达到 WCAG AA。
- `role="alert"` 用于需要立即播报的动态错误，`role="status"` / `aria-live="polite"` 用于加载或预览状态等非紧急变化，不得为精简模板删除。
- 因项目模板不使用 `h1`–`h6`，真实页面、区块和受控 Markdown 标题使用 `role="heading"` 与 `aria-level` 恢复标题导航语义，不得只保留视觉样式。
- 只有实际实现 ARIA Menu 方向键、Home/End 与焦点管理时才使用 `menu/menuitem`；普通导航链接和操作按钮保留原生语义，不额外声明 menu role。

### 5.7 Element Plus 样式覆盖

- 对所有页面生效的 `.el-*` 原生类覆盖集中维护在 `apps/web/src/styles/element.css`，由 `main.ts` 在 Element Plus 基础样式之后全局引入一次；该文件不得包含页面或业务组件前缀。
- 只服务于一个页面或组件的 Element Plus 覆盖必须写在对应 SFC 的 `<style scoped>` 中。优先直接样式化挂到 Element 组件根节点的业务 class；只有必须命中第三方组件内部 DOM 时才可在业务根 class 下使用范围最小的 `:deep()`，禁止 `:global()`。
- 通用覆盖必须直接使用 Element 原生类，不得为迁移本身新增业务 class；只有同一变体已在多个页面稳定复用时，才把语义 class 直接传给对应 Element 组件，Teleport 浮层使用 `popper-class` 等官方入口，再由 `element.css` 组合限定。
- 修改 Element 主题前必须从当前 workspace 确认实际 `element-plus` 版本，并以该版本本地 `theme-chalk` 的官方变量为准；优先覆盖 `--el-*`，只有官方未暴露变量或变量不能覆盖结构问题时才增加带原因注释的最小原生类选择器。
- 根级 `ElConfigProvider` 固定提供 `default`，业务组件不得按视口重复判断 Element 控件尺寸。主题需要兼容显式 large / small 时，必须把外框高度统一映射到当前默认控件 token，并同步处理 padding、字号、圆角和图标/内容间距，禁止只覆盖 height。
- 新增或修改覆盖后必须复扫业务 SFC 中的 `.el-*` 选择器，并运行 Stylelint、ESLint、typecheck、相关组件测试和生产构建。
- Drawer 的 header、body、footer、底部圆角和拖拽把手统一由 `element.css` 的原生 `.el-drawer*` 规则提供；Dialog/Drawer 的 Close 按钮由 `.el-dialog__headerbtn` / `.el-drawer__close-btn` 共用带边框的圆形外观、尺寸和交互态。Close 的 hover/focus/active 不得把边框改为主色，只通过图标色与背景色阶反馈。业务 SFC 不得手写第二套弹层外观，只允许保留尺寸、方向、最大高度和正文业务布局；必须使用自定义 Close 时也需对齐该共享规格。
- `.el-button + .el-button` 只负责把 Element Plus 默认左外边距归零；相邻按钮间距必须由所属 Flex/Grid 操作组的 `gap` 显式提供。新增多按钮工具栏、表格操作列或 Dialog/Drawer footer 时，必须在 PC、Pad、Mobile 对应结构上检查 margin、gap、换行和溢出，禁止同时叠加两套间距。
- Vue 业务模板内的按钮交互统一使用 `el-button`；链接导航保留 `RouterLink` / `<a>`。只有无法由 Vue 挂载组件的受控动态 HTML（例如经 DOMPurify 清洗后由 `v-html` 渲染的行内来源）可保留原生 `<button>`，且必须保留 `type="button"`、键盘语义与委托事件测试。测试桩为模拟 `ElButton` 输出而使用原生 `<button>` 不计入业务模板。
- `el-button` 的 `native-type` 默认为 `button`，普通操作不写 `native-type="button"`；仅表单提交等非默认行为显式使用 `native-type="submit"` 或 `native-type="reset"`。

## 6. NestJS 主服务规范

### 6.1 分层

```text
Controller → Application Service → Domain/Policy
                                → Repository/Provider Adapter
```

- Controller 只处理协议、DTO、身份和响应映射。
- Application Service 编排用例。
- Domain/Policy 保存可独立测试的业务规则。
- Repository、Queue、VectorStore、Provider 属于 adapter。
- 禁止 controller 直接调用 ORM、Chroma 或模型 SDK。

### 6.2 模块

- 按业务领域组织：auth、documents、ingestion、knowledge、providers、audit。
- 模块公开最小接口。
- 避免循环依赖和 `forwardRef` 泛滥。
- 跨模块事件应有明确 schema 和版本。
- Provider SDK 只能在对应 adapter 中初始化。

### 6.3 DTO 与验证

- 所有 HTTP、queue 和 Worker 输入均运行时验证。
- 白名单化字段，拒绝或移除未知敏感字段。
- 客户端 DTO 不接受可信的 `tenantId`、role、department、isAdmin。
- ID、分页、排序、文件和时间范围均限制合法范围。
- 错误返回稳定 code、用户可理解 message 和 traceId。

### 6.4 身份与授权

- Controller 从认证上下文取得 Identity。
- tenant 过滤是所有数据访问的强制条件。
- 管理员也不能跨越 tenant，除非是经过独立审计的平台级操作。
- VectorStore 查询必须由服务端构造 ACL filter。
- 用户不能提交任意 Chroma where 或数据库过滤表达式。
- 资源返回前执行最终授权检查。

### 6.5 Provider

- LLM、Embedding、Rerank 分开接口。
- Provider factory 集中处理配置选择。
- 业务逻辑不得读取具体 API Key。
- 记录实际 provider/model/requestId/usage。
- 将供应商错误转换为统一错误，不把原始敏感响应直接返回客户端。
- 本机 Ollama 只可由 Embedding adapter 使用经 schema 白名单校验的本机端点；不得借“本地”配置接受任意 HTTP URL，也不得为它伪造或记录 API Key。
- Ollama Embedding 使用原生 `/api/embed` 时必须显式关闭静默截断、约束 `keep_alive`，校验模型与向量空间，并记录 Provider 总耗时和模型加载耗时；仅在合成探针证明新旧接口向量完全一致时，传输层切换才可不触发索引迁移。
- Google Embedding 只通过 `@google/genai` adapter 调用，document/query task rule 必须固定为契约允许值；不得在业务 service 中拼装 Google 请求。

## 7. Python Parser Worker 规范

### 7.1 职责限制

Worker 只解析文档并返回结构化元素，不实现：

- 用户认证业务。
- ACL。
- Embedding、Rerank 或 LLM。
- Chroma 写入。
- 文档生命周期和版本激活。

### 7.2 Python 风格

- Python 3.11。
- 所有公共函数和 schema 使用类型注解。
- 使用 Pydantic 校验请求和响应。
- 集合默认值使用 `Field(default_factory=...)`。
- 使用统一 formatter、linter 和 type checker。
- 不使用裸 `except:`。
- 捕获异常时保留内部错误链，但对外转换为安全错误码。
- 文件句柄和临时资源使用 context manager。

### 7.3 文件安全

- 解析前验证解析路径位于允许根目录。
- 解析真实路径后再次验证，防止符号链接逃逸。
- 根据扩展名、MIME 和 magic bytes 选择允许的解析器。
- 设置大小、页数、解压数量、处理时间和资源上限。
- 临时文件只放受控目录，任务结束清理。
- 不把用户文件名拼接为任意命令行。
- 调用 LibreOffice/Tika 等外部程序时使用参数数组，不拼接 shell 字符串。
- DWG 转换器必须使用服务端配置的绝对可执行路径，不从 `PATH` 自动发现，不跟随符号链接；请求不得传入可执行路径、输出目录或任意转换参数。
- 外部转换在任务私有临时目录执行，使用最小环境变量并限制超时和输出大小；结束时无论成功失败都清理产物。
- 持久预览产物只能写入受控的 `PREVIEW_ARTIFACTS_PATH`；单文件名必须是当前 `documentId` 加白名单扩展名，CAD bundle 只允许 `<documentId>.cad/bundles/<server-generated-uuid>/...`；不接受请求传入输出路径。所有 pointer、manifest 和瓦片路径都必须校验真实路径、符号链接与根目录边界。
- CAD SVG 必须移除脚本、链接、外部图片、`foreignObject`、事件属性和 href，并由 API 增加 `nosniff` 与限制性 CSP。
- Office/CAD 预览镜像必须包含经固定包管理器安装的 CJK 字体；LibreOffice 生成 PDF 时应嵌入实际中文字形，ezdxf 默认字体不含目标字形时必须切换到本地 CJK 字体后再生成 SVG 路径，不依赖用户浏览器字体。

### 7.4 解析结果

- 每个元素必须有 text 和 elementType。
- 尽可能保留 page、sheet、sectionPath 和 bbox。
- 空文本视为解析失败或明确 warning。
- OCR 结果保存置信度和 warning。
- 返回 parser 和 parserVersion。
- CAD 二维文字关系只能由同一 layout/块坐标系内的受控空间规则恢复；标题栏键值配对必须使用高置信字段白名单、右侧同行最近值和有界元素数，并保留坐标/handle 证据。不得跨坐标系拼接、靠放大全局邻居窗口掩盖解析缺陷，或在数据库中手工改写既有 chunk。
- CAD 文件级标题汇总只能复制已通过空间配对的字段，必须限制字段数、字符数并保留 layout；不能把任意原始文字纳入汇总。文档名线索召回只能在服务端 ACL 查询出的 active 文档内生成 documentId 白名单，并在 VectorStore 再次叠加完整 ACL，禁止接受客户端 document scope。
- 不在普通日志输出完整文档正文。
- 预览生成结果是可选解析附件；失败返回稳定 warning 并继续 RAG 入库，不得用预览转换器替代正式解析结果。
- 预览交互必须保持内容块内滚动；全屏入口适用于所有预览状态，CAD 缩放需有限上下界、可重置并有可访问名称。瓦片以服务端 manifest 的受控 `maxZoom<=15` 为事实源，并结合设备像素比限制最高层级后的位图拉伸；前端不得覆盖旧 bundle 或受控下调后的较低上限。两类查看器的缩放必须保持同一相机语义：按钮保留视窗中心，Ctrl/Command + 滚轮保留指针下的内容点，不能只修改尺寸后沿用旧滚动偏移。SVG 与瓦片 CAD 都必须显示统一的“拖动定位”提示和当前视窗框，不重复显示“鸟瞰图”标题；有 `focusBounds` 时额外显示主体/全图范围切换，两种鸟瞰资源都必须走相同 ACL，坐标转换保持可逆且全图模式明确标出主体位置。渐进完整索引完成后前端只刷新一次鸟瞰，失败时保留原总览。改动任一策略时需覆盖正常边界、远距离群实体、z15、设备像素比、连续中心缩放、指针锚点、主体/全图切换、彩色鸟瞰刷新和鸟瞰定位回归测试。
- 超大 CAD 不得全量预生成所有瓦片。入库只生成总览、复用总览的 z0 和服务端数值型几何索引；细节由受固定参数、超时和内存上限保护的子进程按需生成。
  - 几何索引不得使用 pickle 或其他可执行反序列化格式；一个 metatile 必须一次查询、一次组合绘制后原子裁图，不得为相邻瓦片重复解析完整 DXF。
  - 初始化预算可大于单瓦片预算，但必须有硬上限。写入原子且幂等；父进程在文档锁内回收被强杀子进程遗留的受控 UUID 临时目录。
  - 磁盘缓存必须有 LRU 上限；缓存命中读取不得排在文档级未命中渲染锁之后。旧 bundle 的几何索引升级复用初始化预算，并保持相同的路径、符号链接、内存和删除约束。
- CAD manifest 必须包含受限的完整 `bounds`、层级/瓦片尺寸、`worldToPixel` 与渲染成本分；用于动态细节层级和可选 `focusBounds` 的主要几何范围只能通过有界内存、确定性采样和固定比例稳健统计计算，并与实际渲染可见性一致。关闭/冻结图层及实体自身隐藏的图元仍可保留在完整索引与 `bounds`，但不得参与主体样本。`focusBounds` 必须位于完整 `bounds` 内，只能影响首次/重置相机，不能裁掉完整范围、删除图元或改变瓦片坐标。前端回归必须同时覆盖旧 manifest 回退、主体初始瓦片坐标、重置、鸟瞰远距导航、`AbortController`、并发上限、边缘预取和 GPU 资源释放。
- 复杂 CAD 的快速初始化不得把总览 PNG 或抽样图元伪装成最终多级细节。快速 bundle 可用有界抽样生成总览，但首次细节请求必须从受控 DXF 原子建立完整、非可执行的世界坐标几何索引；完整路径必须展开块引用、保留解析后的颜色。连续曲线或文字轮廓可压缩为单个纯数值 polyline 索引记录，但必须保留相同 z 层级扁平精度、颜色和全部顶点，同时继续执行单记录、记录数、bundle、时间与内存硬上限；不得用降低几何精度、丢线或扩大无界 BLOB 规避容量错误。完整索引完成后从该索引原子替换全图鸟瞰、z0 与可选主体鸟瞰，最后写内部完成标记。已有缓存瓦片但缺少完成标记时必须补齐鸟瞰，不能永久返回单色快速总览；异常终止遗留的、仅匹配受控几何索引临时命名规则的文件必须在下一次持锁构建前删除。前端在完成索引前只能保留一个初始化请求，失败后停止自动预取，不能形成串行重复构建；任一硬上限触发时失败关闭，禁止静默截断。ASCII OCS 坐标必须转换为 WCS，未展开块的裸 `INSERT` 点不得参与可见边界。回归至少覆盖完整模型空间不跨实体抽样、嵌套/重复块变换、BYLAYER/BYBLOCK 颜色、复合路径格式兼容、完整索引后的多色全图、缓存瓦片补刷新、异常临时索引清理、渐进 single-flight、高层级瓦片、非默认 extrusion、远距空块引用以及失败后不留下半成品索引或完成标记。

## 8. API 规范

机器可读字段契约以 `packages/contracts/openapi/api.v1.yaml` 为事实源；面向调用方的行为说明见 [07-API使用说明.md](./07-API使用说明.md)。接口变更必须同步运行时 Zod 契约、OpenAPI、实现、测试和使用说明，不得只修改其中一处。

### 8.1 基本约定

- 路径使用 `/v1` 版本前缀。
- 资源使用复数名词。
- 对外 JSON 使用 camelCase。
- 时间使用 ISO 8601，并包含时区。
- 分页使用项目统一的 cursor 或 page 方案，不混用。
- 列表排序字段使用白名单。
- 创建异步任务返回资源 ID 和 jobId。

### 8.2 状态码

- `200`：成功查询或更新。
- `201`：成功创建资源。
- `202`：已接受异步处理。
- `204`：成功且无响应正文。
- `400`：请求格式或参数错误。
- `401`：未认证或会话失效。
- `403`：已认证但无权限。
- `404`：资源不存在或为避免泄露而不可见。
- `409`：重复、版本或状态冲突。
- `413`：文件过大。
- `422`：语义验证失败（项目需统一 400/422 的边界）。
- `429`：限流。
- `500/502/503/504`：内部或上游故障。

### 8.3 错误格式

```json
{
  "error": {
    "code": "DOCUMENT_PARSE_FAILED",
    "message": "文档解析失败，请检查文件格式后重试",
    "traceId": "uuid",
    "details": []
  }
}
```

- code 稳定并可用于前端映射。
- message 不暴露内部路径、堆栈、SQL、Key 和供应商敏感响应。
- field errors 可以放入受控 details。

### 8.4 幂等

- 上传和 mutation 支持 idempotency/client request ID。
- BullMQ job 使用稳定 ingestionJobId。
- 向量写入使用稳定 chunkId 和 upsert。
- 删除与重试在重复调用时保持安全结果。
- reindex 不得在候选向量回读确认前清空或替换 active version；全量索引迁移必须先完整准备候选，再用单一 transaction 切换，不能逐文档边重建边暴露不完整的新向量空间。

## 9. 数据库与数据规范

- PostgreSQL 是文档、ACL、任务和 active version 的事实源。
- Chroma 是可重建索引，不是权限事实源。
- Redis 不是长期业务事实源。
- 所有业务表包含明确主键和时间字段。
- tenant 数据表必须包含 tenantId，并建立合适索引。
- 唯一约束和外键优先由数据库保证，不只靠应用判断。
- schema 变更必须使用迁移。
- 已发布迁移不得修改；新增迁移进行修正。
- 生产迁移采用 expand/contract，避免直接破坏兼容性。
- 删除策略明确区分软删除、物理删除和审计保留。
- 敏感字段不得出现在无保护的 JSON dump 和调试日志。

## 10. 日志、审计与可观测性

### 10.1 应用日志

统一结构化字段：

```text
timestamp level service traceId tenantId userId
jobId documentId provider model durationMs status errorCode
```

不得记录：API Key、Authorization、Cookie、密码、完整问题、完整回答、完整文档片段、未脱敏个人信息。

### 10.2 审计

- 权限修改、文档上传/删除、Provider 修改、索引切换和导出必须审计。
- 审计记录资源 ID 和 chunk ID，不默认保存正文。
- 审计事件不可由普通用户修改。
- 审计失败时，高风险操作应按策略失败关闭或进入可靠补偿队列。
- 查询审计只保存问题长度、结果状态、Provider/model、资源 ID、chunk ID、耗时和错误码，不保存问题、回答或片段正文；查询审计写入失败时回答不得返回。
- tenant 级审计查询必须要求独立 `audit:read` capability，并在每张审计表查询中显式带 tenantId；管理员角色本身不能替代 capability，也不能跨 tenant。
- 检索、Rerank、LLM 和引用返回之间都可能发生权限变化，每个出网或返回边界必须重新鉴权 active version，不能复用早期检查结果作为最终授权。

### 10.3 指标

- 标签必须控制基数，不能把 userId、documentId、traceId 作为 Prometheus 高基数 label。
- 这些 ID 放日志/trace，而不是指标标签。
- Provider 延迟、错误率、用量和成本分开统计。
- 成本只按经过校验的显式 `provider:model` 价格表估算；价格缺失时保留 token 用量，不得填充猜测价格。
- CAD 瓦片指标只使用受限 `zoom=0..15`、`cache=hit|miss|unknown` 和成功/失败 label；用于计算瓦片耗时 p95、缓存命中率和实际层级分布，不得加 documentId。

## 11. 测试规范

### 11.1 测试层级

- 单元测试：纯业务规则、转换和组件行为。
- 契约测试：前后端、主服务/Worker、Provider adapter。
- 集成测试：PostgreSQL、Redis/BullMQ、Chroma。
- 端到端测试：登录、上传、入库、查询、来源、删除和权限。
- 质量评测：RAG Recall、引用正确率、拒答和成本，不与普通单元测试混淆。

### 11.2 测试要求

- 测试命名描述行为和结果。
- 每个 bug 修复先增加可复现测试或在同一改动中补充回归测试。
- 时间、随机数、UUID 和外部服务应可注入或控制。
- 测试不得依赖执行顺序。
- fixture 不包含生产数据和真实密钥。
- 付费 Provider 测试默认关闭，显式开关启用。
- 真实评测集只能进入 Git 忽略的私有目录；普通测试使用明确标记的脱敏合成 case，不能冒充真实问题。
- 评测 run 必须覆盖同一数据集的全部 case，不能删除失败、无答案或无权限样本来改善指标。
- 越权泄露率必须先于质量增益判断；任一策略越权率非零时不得建议上线 Rerank。
- 单次成本缺失时报告必须显示覆盖率不足，不能用跨请求平均值或猜测价格补齐。
- 不使用过度 snapshot 隐藏业务断言。
- 安全测试不得仅验证导航隐藏，必须验证后端返回 403/404。

### 11.3 必测安全场景

- tenant 交叉访问。
- 客户端伪造角色、部门和 tenantId。
- confidential 零云端调用。
- 上传路径穿越和符号链接。
- 非法 MIME 和超限文件。
- 文档 prompt injection。
- Provider 密钥不回显。
- 删除后向量不可检索。
- Embedding 指纹不一致时阻止 ready/写入。

### 11.4 覆盖率

不以单一覆盖率数字替代测试质量。安全策略、状态机、Provider 错误映射和索引迁移必须有明确分支测试。

## 12. Git 与提交规范

### 12.1 分支

- 默认分支受保护。
- 功能和修复使用短生命周期分支。
- 分支名示例：`feat/document-upload`、`fix/acl-filter`、`docs/frontend-design`。
- 一个分支聚焦一个可审查目标。

### 12.2 Commit

建议使用 Conventional Commits：

```text
feat: add document upload job
fix: enforce tenant filter before vector query
docs: add Vue frontend design
test: cover confidential cloud-block policy
refactor: extract embedding provider factory
chore: update locked dependencies
```

- Commit 应可解释且范围清晰。
- 不提交生成数据、构建产物、日志和密钥。
- 不把无关格式化和业务修改混在一起。
- 不重写或删除他人未确认的工作。

### 12.3 Pull Request

PR 说明至少包含：

- 目标与背景。
- 主要改动。
- 安全和数据影响。
- 验证命令与结果。
- 数据库/索引/配置迁移。
- UI 改动截图（涉及前端时）。
- 未完成项和回滚方式。

## 13. 依赖管理

- 使用 pnpm workspace 和锁文件。
- Python 使用锁定的 requirements/lock 文件。
- CI 使用 frozen lock。
- 新增依赖前确认用途、维护状态、许可证和安全风险。
- 能用已有依赖或标准库解决时不新增近似依赖。
- 生产镜像固定精确版本，不使用 `latest`。
- 依赖升级单独提交或明确说明行为变化。
- 模型 SDK、Chroma、Unstructured 等升级必须运行契约和集成测试。
- 高风险漏洞及时升级；无法立即升级时记录缓解措施和截止日期。

---

## 14. 配置与密钥

- 配置通过统一 schema 校验。
- 缺少必需配置时启动失败。
- 根目录 `.env.example` 是唯一完整的可复制配置清单，只含占位值，且每个配置项必须有紧邻的用途说明；其他文档只链接它或提供面向单一场景的最小片段，不复制完整清单。
- 新增、重命名或删除环境变量时，同一变更必须更新 schema、`.env.example`、Compose 传递规则、测试和受影响的解释性文档。
- local、test、production 使用不同凭据和资源。
- 前端只允许暴露明确标记为公开的构建配置。
- 模型 API Key 只存在主服务端。
- Parser Worker 只持有内部调用 token。
- 日志中的配置摘要必须脱敏。
- 密钥轮换不要求重新构建前端镜像。
- 本机 Ollama 不需要 API Key，但仍必须通过配置 schema 限制为受控本机地址，防止文档或查询内容被误送往未批准端点。

## 15. 性能规范

- 文件上传使用流式处理。
- 大文件解析进入异步队列。
- Redis job payload 不包含文件正文。
- Embedding 按供应商限制批量处理并设置并发上限。
- 前端列表使用服务端分页。
- 搜索使用合理 debounce。
- 不在 Vue render/computed 中执行昂贵副作用。
- CAD 瓦片请求必须对连续缩放/拖动防抖，只加载最终视口；可见瓦片优先于预取，浏览器并发上限必须与 Worker 实际渲染并发匹配。
- 不在 NestJS 请求线程同步执行 OCR 或大型解析。
- 性能优化必须基于指标和 profile，不靠猜测。
- 新缓存必须定义 key、tenant 隔离、TTL、失效和敏感数据策略。
- Embedding 缓存键必须由 tenant、文本哈希、Provider、模型、维度、任务模式/规则、分块参数、脱敏版本和整体指纹共同生成；策略拒绝必须发生在缓存读取之前。
- Embedding 批次只有在缓存落库与任务 checkpoint 成功后才算完成；测试必须覆盖中间批次失败后重试不再调用已缓存批次的 Provider。不得仅写 `embedding_batch:*` 字符串就宣称支持批次续跑。
- 对话历史只能在服务端验证 tenant + user 所有权后读取，并设置轮次与字符硬上限。用于指代消解时只传递由服务端记录、且敏感度与当前问题一致的近期用户问题；敏感度未知或不一致时失败关闭，不得无条件把历史助手答案或来源正文重新发送到云端。
- Rerank 候选预算与 LLM 生成上下文预算必须分离；生成上下文按相关度优先收敛，以减少输入 token 和首 token 延迟，同时保留 LLM 前与回答返回前的强制授权复核。
- Rerank 关闭时最终返回数仍必须使用 `RERANK_TOP_K`；为清理旧版本或相同 CAD 标注造成的候选挤占，可在完整 ACL、`QUERY_RECALL_TOP_K` 硬上限和原距离阈值内有界过取，但必须在 active version 相邻块扩展后折叠完全相同正文并收敛到最终 Top K；该过程不得计算或伪造 Rerank 分数。
- Query Embedding 缓存命中的滑动 TTL 更新应节流，过期行清理不得无条件位于每次问答的热路径。
- Grounded 模型明确输出“资料不足”时不得执行引用格式修复；缺失或越界引用仍只允许在相同授权上下文中修复一次。必须分别监控显式依据不足、引用缺失、越界、修复成功和修复失败，不能为降低延迟取消校验。

## 17. Definition of Done

一项任务只有同时满足以下条件才能标记完成：

1. 代码实现满足需求和架构边界。
2. 成功、失败和关键权限测试通过。
3. lint、typecheck、test 和 build 通过。
4. 必要的数据库、索引和配置迁移已提供。
5. 不含密钥、生产数据、日志和本机绝对路径。
6. API/Worker 契约同步。
7. 相关项目文档和 `.env.example` 已更新。
8. 前端变更提供必要截图或交互说明。
9. 部署影响、回滚方式和未完成风险已说明。
10. 实际验证结果被如实记录，未运行的测试不得声称通过。

## 18. 规范例外

确需偏离规范时，必须在任务或 PR 中记录：

- 偏离哪条规则。
- 为什么无法遵守。
- 安全与维护影响。
- 临时缓解措施。
- 负责人和修复期限。

安全边界、租户隔离、密钥保护和 Embedding 索引兼容性不得作为普通规范例外被绕过。
