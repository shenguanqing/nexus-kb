## 2. 通用工程原则

### 2.1 优先级

1. 安全和租户隔离。
2. 数据正确性和可恢复性。
3. 清晰、可测试和可维护性。
4. 用户体验和性能。
5. 开发便利性。

不得为了少写代码而降低权限、审计、幂等或错误处理要求。

### 2.2 代码原则

- 保持模块职责单一。
- 优先使用小而明确的接口，不建立万能 service。
- 业务逻辑不放在 controller、Vue 页面组件或基础设施 adapter 中。
- 外部输入必须运行时校验。
- 显式处理失败，不吞异常。
- 避免全局可变状态和隐式副作用。
- 重要算法和安全决策说明“为什么”，不要用注释重复代码。
- 不为未知需求提前构建复杂抽象。
- 删除无用代码，不长期保留注释掉的旧实现。
- 不复制粘贴形成两套近似业务流程。

### 2.3 语言

- 代码标识符使用英文。
- 用户界面和面向用户的错误信息使用简体中文，预留国际化能力。
- Git commit 可使用中文或英文，但仓库内保持统一。
- 技术文档以中文为主，必要的标准名词保留英文。

## 3. 仓库与目录

```text
apps/
├── web/                    Vue 3 前端
├── api/                    NestJS 主服务
└── parser-worker/          Python 解析 Worker
packages/
├── contracts/              DTO、事件和生成契约
└── config/                 可共享的开发配置
docs/                       项目文档
```

规则：

- 业务代码只能放入对应 app/module。
- `packages/contracts` 不依赖具体 UI、数据库或 Provider SDK。
- 不从一个 app 直接引用另一个 app 的内部源码。
- 跨服务通过契约或公开 package 通信。
- 测试 fixture 放在明确的 `test/fixtures`，不得混入生产数据目录。
- 上传文件、向量数据、数据库文件和日志不得进入 Git。

## 4. TypeScript 通用规范

### 4.1 编译与类型

- 开启 `strict`。
- 禁止无说明的 `any`；外部未知数据先使用 `unknown`，验证后再缩窄。
- 禁止使用 `@ts-ignore` 隐藏问题；确有必要时使用带原因的 `@ts-expect-error`。
- 公共函数、Provider 接口和 DTO 使用明确类型。
- 避免不安全的非空断言 `!`。
- 优先使用判别联合表达状态，而不是多个可能冲突的 boolean。

推荐：

```ts
type IngestionState =
  | { status: 'queued' }
  | { status: 'processing'; step: IngestionStep; progress: number }
  | { status: 'completed'; documentVersion: number }
  | { status: 'failed'; errorCode: string; retryable: boolean };
```

不推荐：

```ts
interface State {
  loading: boolean;
  completed: boolean;
  failed: boolean;
}
```

### 4.2 命名

- 类型、类、Vue 组件：PascalCase。
- 函数、变量、composable：camelCase。
- 常量：对真正全局不可变值使用 UPPER_SNAKE_CASE。
- 文件名遵循各框架惯例，项目内保持一致。
- boolean 以 `is`、`has`、`can`、`should` 开头。
- 集合使用复数名。
- 不使用含义不明的 `data`、`info`、`item` 作为跨越大作用域的名称。

### 4.3 异步代码

- 使用 `async/await`，避免无必要的 Promise 链嵌套。
- 所有外部请求设置超时。
- 并发批次必须有上限，不能对大数组直接无限 `Promise.all`。
- 不创建未处理的 floating Promise。
- 取消、超时和重试必须区分。
- 非幂等操作不自动无限重试。

### 4.4 格式和静态检查

- 使用统一 ESLint 和 Prettier 配置。
- CSS、SCSS 和 Vue SFC 的样式声明使用根目录 `stylelint.config.cjs` 定义的语义分组顺序； `pnpm format:css` 自动修复，`pnpm lint:css` 只检查不修改。分组之间不插入空行，未列出的属性统一置于末尾并按字母排序。
- VS Code / Cursor 使用工作区推荐的 Stylelint 扩展，并通过 `.vscode/settings.json` 在保存 CSS、SCSS 或 Vue 文件时自动修复声明顺序。
- VS Code / Cursor 使用工作区推荐的 Prettier 扩展，在保存 JSON、JSONC 和 Vue 文件时自动格式化。
- 不在局部目录创建相互冲突的格式配置。
- 提交前必须通过 lint、typecheck、test 和 build。
- 禁止通过大范围 disable 关闭 lint 规则。

## 5. Vue 前端规范

### 5.1 组件

- 使用 Vue 3 Composition API 和 `<script setup lang="ts">`。
- 页面组件负责组合，复杂业务逻辑下沉 composable/service。
- 通用组件不直接访问路由、Pinia 或具体业务 API，除非组件职责明确要求。
- props 和 emits 必须有类型。
- 双向绑定只用于真正的表单状态，避免跨层级隐式修改。
- 一个组件过大或同时承担数据获取、权限、布局和复杂交互时必须拆分。

### 5.2 状态

- Pinia 保存身份摘要、导航和界面偏好。
- 服务端数据由 query/composable 层管理。
- 不把 API 响应无差别复制进全局 store。
- 不在 `localStorage` 保存完整问答、来源片段、API Key 或权限敏感数据。
- 登出时清空身份、query cache 和敏感页面状态。

### 5.3 路由与权限

- 使用 Vue Router route meta 声明认证和 capability。
- 管理页面还必须声明管理员角色门槛；普通用户仅可访问知识问答和个人问答历史。
- route guard 只负责前端体验，不替代后端鉴权。
- API 返回 403 时显示无权限，不自动当作未登录。
- 未登录与无权限必须区分。
- 页面刷新后重新加载服务端身份，不能只信任浏览器缓存角色。
- 账号密码表单只可提交到同源认证 API；密码在成功或失败后立即清空，禁止写入 Pinia、localStorage、URL、日志、analytics、错误监控或 session replay。浏览器会话仅依赖服务端签发的 HttpOnly Cookie。

### 5.4 表单

- 所有字段有 label、验证状态和可操作错误信息。
- 前端验证用于即时反馈，后端仍完整验证。
- 防止重复提交，mutation 使用 client request ID 或幂等机制。
- 危险操作明确展示影响对象和范围。
- Provider 密钥提交后立即清空，不回显现有值。

### 5.5 内容安全

- 模型回答和文档片段默认作为文本或受控 Markdown 渲染。
- 禁止 `v-html` 渲染未经严格清洗的模型或文档内容。
- 受控 Markdown 必须复用统一组件：解析器关闭原始 HTML，输出再经过标签、属性和 URI 协议白名单清洗；不允许页面各自实现正则替换或独立放宽规则。
- 外部链接只允许批准的安全协议，并增加 `noopener noreferrer`；图片、iframe、SVG、表单和其他隐式加载或可执行嵌入默认禁止。
- 不执行回答中的脚本、iframe、事件属性和嵌入组件。
- 错误监控和 analytics 不采集问题正文、回答、文档片段和密钥输入。
- 混合回答必须通过契约字段区分 `grounded` 与 `general`，不能根据“是否看起来像通用知识”由前端猜测。
- 通用回答只允许空 contexts，必须经过问题敏感度出网策略；权限变化、confidential 阻止和 Provider 错误不得静默伪装成成功的通用回答。
- 正式 RAG 质量评测必须使用严格回答模式，避免通用知识回答污染 Recall、引用和无答案拒答指标。

### 5.6 可访问性

- 图标按钮必须有可访问名称。
- 弹窗正确管理焦点。
- 表单错误与字段关联。
- 状态不能只依赖颜色。
- 核心流程支持键盘。
- 尊重 reduced motion。
- 对比度达到 WCAG AA。

## 6. NestJS 主服务规范

### 6.1 分层

```text
Controller → Application Service → Domain/Policy
                                → Repository/Provider Adapter
```

- Controller 只处理协议、DTO、身份和响应映射。
- Application Service 编排用例。
- Domain/Policy 保存可独立测试的业务规则。
- Repository、Queue、VectorStore、Provider 属于 adapter。
- 禁止 controller 直接调用 ORM、Chroma 或模型 SDK。

### 6.2 模块

- 按业务领域组织：auth、documents、ingestion、knowledge、providers、audit。
- 模块公开最小接口。
- 避免循环依赖和 `forwardRef` 泛滥。
- 跨模块事件应有明确 schema 和版本。
- Provider SDK 只能在对应 adapter 中初始化。

### 6.3 DTO 与验证

- 所有 HTTP、queue 和 Worker 输入均运行时验证。
- 白名单化字段，拒绝或移除未知敏感字段。
- 客户端 DTO 不接受可信的 `tenantId`、role、department、isAdmin。
- ID、分页、排序、文件和时间范围均限制合法范围。
- 错误返回稳定 code、用户可理解 message 和 traceId。

### 6.4 身份与授权

- Controller 从认证上下文取得 Identity。
- tenant 过滤是所有数据访问的强制条件。
- 管理员也不能跨越 tenant，除非是经过独立审计的平台级操作。
- VectorStore 查询必须由服务端构造 ACL filter。
- 用户不能提交任意 Chroma where 或数据库过滤表达式。
- 资源返回前执行最终授权检查。

### 6.5 Provider

- LLM、Embedding、Rerank 分开接口。
- Provider factory 集中处理配置选择。
- 业务逻辑不得读取具体 API Key。
- 记录实际 provider/model/requestId/usage。
- 将供应商错误转换为统一错误，不把原始敏感响应直接返回客户端。
- 本机 Ollama 只可由 Embedding adapter 使用经 schema 白名单校验的本机端点；不得借“本地”配置接受任意 HTTP URL，也不得为它伪造或记录 API Key。

## 7. Python Parser Worker 规范

### 7.1 职责限制

Worker 只解析文档并返回结构化元素，不实现：

- 用户认证业务。
- ACL。
- Embedding、Rerank 或 LLM。
- Chroma 写入。
- 文档生命周期和版本激活。

### 7.2 Python 风格

- Python 3.11。
- 所有公共函数和 schema 使用类型注解。
- 使用 Pydantic 校验请求和响应。
- 集合默认值使用 `Field(default_factory=...)`。
- 使用统一 formatter、linter 和 type checker。
- 不使用裸 `except:`。
- 捕获异常时保留内部错误链，但对外转换为安全错误码。
- 文件句柄和临时资源使用 context manager。

### 7.3 文件安全

- 解析前验证解析路径位于允许根目录。
- 解析真实路径后再次验证，防止符号链接逃逸。
- 根据扩展名、MIME 和 magic bytes 选择允许的解析器。
- 设置大小、页数、解压数量、处理时间和资源上限。
- 临时文件只放受控目录，任务结束清理。
- 不把用户文件名拼接为任意命令行。
- 调用 LibreOffice/Tika 等外部程序时使用参数数组，不拼接 shell 字符串。
- DWG 转换器必须使用服务端配置的绝对可执行路径，不从 `PATH` 自动发现，不跟随符号链接；请求不得传入可执行路径、输出目录或任意转换参数。
- 外部转换在任务私有临时目录执行，使用最小环境变量并限制超时和输出大小；结束时无论成功失败都清理产物。
- 持久预览产物只能写入受控的 `PREVIEW_ARTIFACTS_PATH`；单文件名必须是当前 `documentId` 加白名单扩展名，CAD bundle 只允许 `<documentId>.cad/bundles/<server-generated-uuid>/...`；不接受请求传入输出路径。所有 pointer、manifest 和瓦片路径都必须校验真实路径、符号链接与根目录边界。
- CAD SVG 必须移除脚本、链接、外部图片、`foreignObject`、事件属性和 href，并由 API 增加 `nosniff` 与限制性 CSP。
- Office/CAD 预览镜像必须包含经固定包管理器安装的 CJK 字体；LibreOffice 生成 PDF 时应嵌入实际中文字形，ezdxf 默认字体不含目标字形时必须切换到本地 CJK 字体后再生成 SVG 路径，不依赖用户浏览器字体。

### 7.4 解析结果

- 每个元素必须有 text 和 elementType。
- 尽可能保留 page、sheet、sectionPath 和 bbox。
- 空文本视为解析失败或明确 warning。
- OCR 结果保存置信度和 warning。
- 返回 parser 和 parserVersion。
- 不在普通日志输出完整文档正文。
- 预览生成结果是可选解析附件；失败返回稳定 warning 并继续 RAG 入库，不得用预览转换器替代正式解析结果。
- 预览交互必须保持内容块内滚动；全屏入口适用于所有预览状态，CAD 缩放需有限上下界、可重置并有可访问名称。
- 超大 CAD 不得全量预生成所有瓦片。入库只同步生成总览、由总览复用的 z0 和服务端生成的数值型几何索引，细节在固定参数、超时和内存上限子进程内按需生成；几何索引不得使用 pickle 或其他可执行反序列化格式。一个 metatile 必须一次查询、一次组合画布绘制后原子裁图，不得为相邻瓦片重复解析完整 DXF。初始化预算可以大于单瓦片预算但必须有硬上限。写入必须原子且可幂等，父进程必须在文档锁内回收被强杀子进程遗留的受控 UUID 临时目录，磁盘缓存必须有 LRU 上限；缓存命中读取不得排在文档级未命中渲染锁之后。旧 bundle 的几何索引升级必须复用初始化预算并保留同等路径、符号链接、内存和删除约束。
- CAD manifest 必须包含受限的 bounds、层级/瓦片尺寸、`worldToPixel` 与渲染成本分；前端瓦片调度必须覆盖 `AbortController`、并发上限、边缘预取和 GPU 资源释放测试。

## 8. API 规范

机器可读字段契约以 `packages/contracts/openapi/api.v1.yaml` 为事实源；面向调用方的行为说明见 [07-API使用说明.md](./07-API使用说明.md)。接口变更必须同步运行时 Zod 契约、OpenAPI、实现、测试和使用说明，不得只修改其中一处。

### 8.1 基本约定

- 路径使用 `/v1` 版本前缀。
- 资源使用复数名词。
- 对外 JSON 使用 camelCase。
- 时间使用 ISO 8601，并包含时区。
- 分页使用项目统一的 cursor 或 page 方案，不混用。
- 列表排序字段使用白名单。
- 创建异步任务返回资源 ID 和 jobId。

### 8.2 状态码

- `200`：成功查询或更新。
- `201`：成功创建资源。
- `202`：已接受异步处理。
- `204`：成功且无响应正文。
- `400`：请求格式或参数错误。
- `401`：未认证或会话失效。
- `403`：已认证但无权限。
- `404`：资源不存在或为避免泄露而不可见。
- `409`：重复、版本或状态冲突。
- `413`：文件过大。
- `422`：语义验证失败（项目需统一 400/422 的边界）。
- `429`：限流。
- `500/502/503/504`：内部或上游故障。

### 8.3 错误格式

```json
{
  "error": {
    "code": "DOCUMENT_PARSE_FAILED",
    "message": "文档解析失败，请检查文件格式后重试",
    "traceId": "uuid",
    "details": []
  }
}
```

- code 稳定并可用于前端映射。
- message 不暴露内部路径、堆栈、SQL、Key 和供应商敏感响应。
- field errors 可以放入受控 details。

### 8.4 幂等

- 上传和 mutation 支持 idempotency/client request ID。
- BullMQ job 使用稳定 ingestionJobId。
- 向量写入使用稳定 chunkId 和 upsert。
- 删除与重试在重复调用时保持安全结果。
- reindex 不得在候选向量回读确认前清空或替换 active version；全量索引迁移必须先完整准备候选，再用单一 transaction 切换，不能逐文档边重建边暴露不完整的新向量空间。

## 9. 数据库与数据规范

- PostgreSQL 是文档、ACL、任务和 active version 的事实源。
- Chroma 是可重建索引，不是权限事实源。
- Redis 不是长期业务事实源。
- 所有业务表包含明确主键和时间字段。
- tenant 数据表必须包含 tenantId，并建立合适索引。
- 唯一约束和外键优先由数据库保证，不只靠应用判断。
- schema 变更必须使用迁移。
- 已发布迁移不得修改；新增迁移进行修正。
- 生产迁移采用 expand/contract，避免直接破坏兼容性。
- 删除策略明确区分软删除、物理删除和审计保留。
- 敏感字段不得出现在无保护的 JSON dump 和调试日志。

## 10. 日志、审计与可观测性

### 10.1 应用日志

统一结构化字段：

```text
timestamp level service traceId tenantId userId
jobId documentId provider model durationMs status errorCode
```

不得记录：API Key、Authorization、Cookie、密码、完整问题、完整回答、完整文档片段、未脱敏个人信息。

### 10.2 审计

- 权限修改、文档上传/删除、Provider 修改、索引切换和导出必须审计。
- 审计记录资源 ID 和 chunk ID，不默认保存正文。
- 审计事件不可由普通用户修改。
- 审计失败时，高风险操作应按策略失败关闭或进入可靠补偿队列。
- 查询审计只保存问题长度、结果状态、Provider/model、资源 ID、chunk ID、耗时和错误码，不保存问题、回答或片段正文；查询审计写入失败时回答不得返回。
- tenant 级审计查询必须要求独立 `audit:read` capability，并在每张审计表查询中显式带 tenantId；管理员角色本身不能替代 capability，也不能跨 tenant。
- 检索、Rerank、LLM 和引用返回之间都可能发生权限变化，每个出网或返回边界必须重新鉴权 active version，不能复用早期检查结果作为最终授权。

### 10.3 指标

- 标签必须控制基数，不能把 userId、documentId、traceId 作为 Prometheus 高基数 label。
- 这些 ID 放日志/trace，而不是指标标签。
- Provider 延迟、错误率、用量和成本分开统计。
- 成本只按经过校验的显式 `provider:model` 价格表估算；价格缺失时保留 token 用量，不得填充猜测价格。
- CAD 瓦片指标只使用受限 `zoom=0..12`、`cache=hit|miss|unknown` 和成功/失败 label；用于计算瓦片耗时 p95、缓存命中率和实际层级分布，不得加 documentId。

## 11. 测试规范

### 11.1 测试层级

- 单元测试：纯业务规则、转换和组件行为。
- 契约测试：前后端、主服务/Worker、Provider adapter。
- 集成测试：PostgreSQL、Redis/BullMQ、Chroma。
- 端到端测试：登录、上传、入库、查询、来源、删除和权限。
- 质量评测：RAG Recall、引用正确率、拒答和成本，不与普通单元测试混淆。

### 11.2 测试要求

- 测试命名描述行为和结果。
- 每个 bug 修复先增加可复现测试或在同一改动中补充回归测试。
- 时间、随机数、UUID 和外部服务应可注入或控制。
- 测试不得依赖执行顺序。
- fixture 不包含生产数据和真实密钥。
- 付费 Provider 测试默认关闭，显式开关启用。
- 真实评测集只能进入 Git 忽略的私有目录；普通测试使用明确标记的脱敏合成 case，不能冒充真实问题。
- 评测 run 必须覆盖同一数据集的全部 case，不能删除失败、无答案或无权限样本来改善指标。
- 越权泄露率必须先于质量增益判断；任一策略越权率非零时不得建议上线 Rerank。
- 单次成本缺失时报告必须显示覆盖率不足，不能用跨请求平均值或猜测价格补齐。
- 不使用过度 snapshot 隐藏业务断言。
- 安全测试不得仅验证导航隐藏，必须验证后端返回 403/404。

### 11.3 必测安全场景

- tenant 交叉访问。
- 客户端伪造角色、部门和 tenantId。
- confidential 零云端调用。
- 上传路径穿越和符号链接。
- 非法 MIME 和超限文件。
- 文档 prompt injection。
- Provider 密钥不回显。
- 删除后向量不可检索。
- Embedding 指纹不一致时阻止 ready/写入。

### 11.4 覆盖率

不以单一覆盖率数字替代测试质量。安全策略、状态机、Provider 错误映射和索引迁移必须有明确分支测试。

## 12. Git 与提交规范

### 12.1 分支

- 默认分支受保护。
- 功能和修复使用短生命周期分支。
- 分支名示例：`feat/document-upload`、`fix/acl-filter`、`docs/frontend-design`。
- 一个分支聚焦一个可审查目标。

### 12.2 Commit

建议使用 Conventional Commits：

```text
feat: add document upload job
fix: enforce tenant filter before vector query
docs: add Vue frontend design
test: cover confidential cloud-block policy
refactor: extract embedding provider factory
chore: update locked dependencies
```

- Commit 应可解释且范围清晰。
- 不提交生成数据、构建产物、日志和密钥。
- 不把无关格式化和业务修改混在一起。
- 不重写或删除他人未确认的工作。

### 12.3 Pull Request

PR 说明至少包含：

- 目标与背景。
- 主要改动。
- 安全和数据影响。
- 验证命令与结果。
- 数据库/索引/配置迁移。
- UI 改动截图（涉及前端时）。
- 未完成项和回滚方式。

## 13. 依赖管理

- 使用 pnpm workspace 和锁文件。
- Python 使用锁定的 requirements/lock 文件。
- CI 使用 frozen lock。
- 新增依赖前确认用途、维护状态、许可证和安全风险。
- 能用已有依赖或标准库解决时不新增近似依赖。
- 生产镜像固定精确版本，不使用 `latest`。
- 依赖升级单独提交或明确说明行为变化。
- 模型 SDK、Chroma、Unstructured 等升级必须运行契约和集成测试。
- 高风险漏洞及时升级；无法立即升级时记录缓解措施和截止日期。

---

## 14. 配置与密钥

- 配置通过统一 schema 校验。
- 缺少必需配置时启动失败。
- 根目录 `.env.example` 是唯一完整的可复制配置清单，只含占位值，且每个配置项必须有紧邻的用途说明；其他文档只链接它或提供面向单一场景的最小片段，不复制完整清单。
- 新增、重命名或删除环境变量时，同一变更必须更新 schema、`.env.example`、Compose 传递规则、测试和受影响的解释性文档。
- local、test、production 使用不同凭据和资源。
- 前端只允许暴露明确标记为公开的构建配置。
- 模型 API Key 只存在主服务端。
- Parser Worker 只持有内部调用 token。
- 日志中的配置摘要必须脱敏。
- 密钥轮换不要求重新构建前端镜像。
- 本机 Ollama 不需要 API Key，但仍必须通过配置 schema 限制为受控本机地址，防止文档或查询内容被误送往未批准端点。

## 15. 性能规范

- 文件上传使用流式处理。
- 大文件解析进入异步队列。
- Redis job payload 不包含文件正文。
- Embedding 按供应商限制批量处理并设置并发上限。
- 前端列表使用服务端分页。
- 搜索使用合理 debounce。
- 不在 Vue render/computed 中执行昂贵副作用。
- CAD 瓦片请求必须对连续缩放/拖动防抖，只加载最终视口；可见瓦片优先于预取，浏览器并发上限必须与 Worker 实际渲染并发匹配。
- 不在 NestJS 请求线程同步执行 OCR 或大型解析。
- 性能优化必须基于指标和 profile，不靠猜测。
- 新缓存必须定义 key、tenant 隔离、TTL、失效和敏感数据策略。

## 17. Definition of Done

一项任务只有同时满足以下条件才能标记完成：

1. 代码实现满足需求和架构边界。
2. 成功、失败和关键权限测试通过。
3. lint、typecheck、test 和 build 通过。
4. 必要的数据库、索引和配置迁移已提供。
5. 不含密钥、生产数据、日志和本机绝对路径。
6. API/Worker 契约同步。
7. 相关项目文档和 `.env.example` 已更新。
8. 前端变更提供必要截图或交互说明。
9. 部署影响、回滚方式和未完成风险已说明。
10. 实际验证结果被如实记录，未运行的测试不得声称通过。

## 18. 规范例外

确需偏离规范时，必须在任务或 PR 中记录：

- 偏离哪条规则。
- 为什么无法遵守。
- 安全与维护影响。
- 临时缓解措施。
- 负责人和修复期限。

安全边界、租户隔离、密钥保护和 Embedding 索引兼容性不得作为普通规范例外被绕过。
