# NexusKB 本地小白启动与配置指南

> 适用：Mac + Docker Desktop + 本机 Ollama。本指南的推荐组合是 **Ollama `bge-m3:latest` 负责向量化**，
> **Google Gemini `gemini-3.5-flash-lite` 负责回答**。

## 1. 先准备好环境

需要安装并启动：Docker Desktop、Node.js LTS、pnpm，以及 Ollama。

在终端确认 Ollama 已启动且模型存在：

```bash
ollama list
```

预期能看到 `bge-m3:latest`。如果没有，运行：

```bash
ollama pull bge-m3:latest
```

不要把测试文档放进仓库或 Docker volume。建议在仓库外创建目录，例如：

```text
/Users/shenguanqing/Documents/NexusKB-local-tests/
```

把 `工作簿1.xlsx`、`Drawing1.dwg` 等测试文件放在那里，再通过网页的“上传文档”选择它们。

## 2. 创建并填写 `.env`

第一次使用时，在仓库根目录执行：

```bash
cp .env.example .env
```

`.env` 已被 Git 忽略。它只能留在本机；不要发送、提交或截图 `GEMINI_API_KEY`。

保留 `.env.example` 中其他默认值，只确认/替换下列几项：

```dotenv
# 本机 Ollama：不需要 API Key
EMBEDDING_PROVIDER=ollama
EMBEDDING_MODEL=bge-m3:latest
EMBEDDING_DIMENSIONS=1024
EMBEDDING_REGION=local
OLLAMA_BASE_URL=http://host.docker.internal:11434

# Gemini：需要在 Google AI Studio 创建的 Key
LLM_PROVIDER=google
LLM_MODEL=gemini-3.5-flash-lite
GEMINI_API_KEY=在这里粘贴你的真实Key
GEMINI_BASE_URL=https://generativelanguage.googleapis.com/v1beta
GEMINI_REGION=global

# 在取得 ODA 安装包前不要启用 DWG 转换器
DWG_CONVERSION_ENABLED=false
```

`bge-m3` 的向量维度是 1024；不要改成 768 或其他数值。之后若改动 Embedding Provider、模型、维度、分块或关键
脱敏规则，必须建立新索引，不能把新旧向量混写。

`gemini-3.5-flash-lite` 使用 Google 当前的原生接口。应用会自动不发送该模型不再接受的 `temperature` 参数。

## 3. 启动或应用新配置

每次改动 Provider、模型或容器配置后，在仓库根目录执行：

```bash
docker compose up -d --build
docker compose ps
```

全部服务显示运行中后，检查服务是否已就绪：

```bash
curl http://127.0.0.1:3000/health/ready
```

网页的“系统管理 → 模型 Provider”应显示：

- Embedding：`ollama` / `bge-m3:latest` / `local` / “本地无需凭据”；
- LLM：`google` / `gemini-3.5-flash-lite` / “已配置”。

页面刷新只检查配置，不会调用 Gemini，不会产生模型费用。

## 4. “待建立索引”是什么意思

这表示文件已经安全完成解析、分块和脱敏，但当时没有可用的 Embedding Provider，所以还没有向量、不能用于问答。

配置并重启服务后，进入该文档详情，点击 **“继续建立索引”**。系统会直接使用已保存的本地分块来生成向量和建立
Chroma 索引，不会重新上传或解析原文件。完成后状态变为“已生效”。

如果失败，查看“上传与入库任务”中的安全错误码和 trace ID；不要反复上传同一份文件。

## 5. 启用 DWG 测试

你看到的错误表示 `parser-worker` Linux 容器中不存在：

```text
/opt/oda/ODAFileConverter
```

这不是 `.env` 填错，也不是 Mac 上的命令有问题。基础镜像不分发 ODA File Converter；DWG 必须先在 **Linux 版
Parser Worker 镜像** 中安装与该镜像平台匹配的 ODA Converter。Mac 的应用程序不能直接给 Linux 容器使用。

本项目已提供专用的 `compose.dwg.yaml`。在 Apple Silicon Mac 上，它会让 Worker 使用 `linux/amd64`，由
Docker Desktop 兼容运行 ODA 的 Linux x64 安装包；不使用也不能使用 macOS App。请按下列步骤操作：

1. 从 [ODA 官方下载页](https://www.opendesign.com/guestfiles/oda_File_Converter) 下载经许可的 **Linux x64
   Debian (`.deb`)** 包。
2. 将下载的文件重命名为 `oda-file-converter.deb`，放到项目中的
   `apps/parser-worker/vendor/oda/`。这个 `.deb` 已被 Git 忽略，绝不能提交。
3. 构建并启动 DWG 专用 Worker：

```bash
docker compose -f compose.yaml -f compose.dwg.yaml up -d --build
```

4. 找到真实可执行文件和实际安装版本（不要再猜 `/opt/oda/ODAFileConverter`）：

```bash
docker compose -f compose.yaml -f compose.dwg.yaml run --rm --no-deps --entrypoint sh parser-worker -lc \
  'find /opt /usr -type f -name ODAFileConverter -perm -111 -print; dpkg-query -W | grep -i oda'
```

5. 将上一步输出的真实路径和版本填入 `.env`，然后启用：

```dotenv
DWG_CONVERSION_ENABLED=true
DWG_CONVERTER_EXECUTABLE=<上一步显示的真实绝对路径>
DWG_CONVERTER_RELEASE=<上一步显示的实际版本>
```

6. 再次启动，并确认转换器就绪：

```bash
docker compose -f compose.yaml -f compose.dwg.yaml up -d
docker compose -f compose.yaml -f compose.dwg.yaml exec -T parser-worker \
  <上一步显示的真实绝对路径> --version
curl http://127.0.0.1:3000/health/ready
```

最后一个命令返回的 `parserWorker` 检查中应有 `dwgConverter.status=up`。现在即可通过网页上传
`Drawing1.dwg`；任务先显示“正在将 DWG 转为 DXF 并解析”，再建立索引。

在尚未取得官方安装包时，保持：

```dotenv
DWG_CONVERSION_ENABLED=false
```

没有实际安装和版本输出时，不要猜测 `DWG_CONVERTER_RELEASE`，也不要把 `DWG_CONVERSION_ENABLED` 提前设为 `true`。

## 6. 文档数据存在哪里

| 内容 | 本地位置 |
|---|---|
| 原始上传文件 | Docker `raw_docs` volume |
| 文档 metadata、版本、任务、原文和脱敏分块 | PostgreSQL volume |
| 向量和脱敏检索 metadata | Chroma volume |
| 队列状态 | Redis volume；不存文件正文 |

普通停止用 `docker compose down`。不要随意使用 `docker compose down -v`，它会删除本地数据库、向量和原始文件 volumes。

## 7. 编辑器出现 `Cannot find module '@/api/client'`

这是 Vue 3 项目常见的编辑器插件误报。VS Code 中安装并启用 **Vue - Official (Volar)**，禁用 Vetur，随后执行
“TypeScript: Restart TS Server”或重启编辑器。项目的前端类型检查命令是：

```bash
pnpm --filter @nexus-kb/web typecheck
```
